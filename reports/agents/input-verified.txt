#1 Right stick still flies helicopters and airplanes while a mod panel is being scrolled
VERDICT: CONFIRMED
Reason: VehicleInput.cs:33-35 (Helicopter) and :41-43 (Airplane) read VRInput.TurnStick directly, not VRGameInput.TurnStickRaw. GameInputBridge.cs:96-97 zeroes only MoveStick and TurnStickRaw when scrollingPanel, so the raw right stick is never zeroed. The guard in ShouldDrive (VehicleInput.cs:47-48) checks GameMenuOpen, which is c.IsCursorFree() (GameContext.cs:59-68). The mod never frees the cursor for its panels (grep of src finds no Cursor or lockState use), so the guard does not trip. UISystem.cs:124-128 opens Settings with no seat check. VRRig.cs:435 already blocks snap turn on SticksOnPanel, so only the aircraft path is missing the check.
Trigger: seated as pilot of a helicopter or airplane; open the VR settings (or Mod keys) panel; point the laser at it so SticksOnPanel is true; push the right stick to scroll.
Effect: FlightStick ?? right feeds cyclic/roll (VehicleInput.cs:35, :43), and HelicopterInputPatch / AirplaneInputPatch add it to the game's input (:72, :84), so the aircraft pitches and rolls while the panel is scrolled.
Fix: use VRGameInput.TurnStickRaw in Helicopter() and Airplane(), or return zero for the right stick when VRGameInput.SticksOnPanel is true (same guard VRRig.cs:435 uses).

#2 Sprint toggle pressed while standing still cancels itself in the same frame and clears crouch/prone
VERDICT: CONFIRMED
Reason: GameInputBridge.cs:302-309: the press sets SprintActive = true and clears CrouchToggled and ProneToggled. Lines 312-316 then set SprintActive = false in the same call when MoveStick.sqrMagnitude < 0.04 and Time.unscaledTime - _idleSince > 0.35. _idleSince only moves while the stick is pushed (:319-322), so a stationary press is cancelled at once. Nothing between these lines reads SprintActive; HoldingSprintPatch (:544-553) reads it later and sees false. No guard found.
Trigger: SprintMode Toggle (the default, VRConfig.cs:184); stick idle for more than 0.35 s; press Sprint.
Effect: the press does nothing, and the crouch/prone toggles are cleared for nothing.
Fix: reset _idleSince = Time.unscaledTime when sprint is switched on, and clear the stance toggles only once sprint is actually moving.

#3 A targeted tap on left shift becomes a broadcast hold while sprinting
VERDICT: CONFIRMED
Reason: VRManager.cs:159 calls ScriptKeys.SetHeld("left shift", SprintActive && PlayerOnFoot) every frame. ModKeysPanel.cs:193 calls Tap(key, target), which sets Target and ReleaseAt = now + 0.08 (ScriptKeys.cs:80-90). With a tap in flight, SetHeld(true) gets past both early returns (ScriptKeys.cs:103-106 needs ReleaseAt == MaxValue; 107-110 only guards held == false), so lines 111-117 run: Down stays true, ReleaseAt = MaxValue, Target = null, ChangeFrame refreshed, delivery maps cleared. Query (:184-186) then answers every script. The override happens on the next frame, so any tap while sprinting is broadcast and held until sprint ends (SetHeld(false) then releases normally).
Trigger: sprinting on foot; tap a Mod keys entry for a script that polls left shift.
Effect: the tap reaches every script, not just its target, and stays held for the whole sprint, which defeats the single-target design in ScriptKeys.cs:33-35.
Fix: in SetHeld, when held is true and a tap is in flight (ReleaseAt != MaxValue), leave Target and ReleaseAt alone; or give the sprint hold its own VirtualKey name.

Fix idea: test in headset (Vive, weapon in left hand, auto fire; Touch, squad hold under swap). If the complex outputs are not held, bind the held actions (Squad, Use) to plain click outputs on both sides, or keep hold gestures on the same mode in both layouts.
