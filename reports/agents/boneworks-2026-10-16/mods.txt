MECHANICS
- Hooking model: every mod patches the game through Hooking.CreateHook (HarmonyLib underneath). It picks the caller's own HarmonyInstance, queues hooks made before Harmony exists, and exposes the patches as static events (OnPreFireGun, OnPostFireGun, OnGripAttached, OnGripDetached, OnGrabObject, OnReleaseObject, OnPlayerDeath, OnReloadScene, OnSaveSpotCheckpoint). Features subscribe to those events.
- Game methods that the mods patch (grep of typeof(...).GetMethod and HarmonyPatch): Gun.OnFire, Gun.Fire, Gun.PullCartridge, Gun.EjectCartridge, Gun.CompleteSlidePull, Gun.UpdateArt, CaseEject.ForceInDirection, MagazineSocket.OnPlugLocked, AmmoPouch.OnSpawnGrab, Hand.AttachObject/DetachObject, Grip.OnAttachedToHand/OnDetachedFromHand, GunSFX.SlideRelease, PumpSlideGrip.OnAttachedToHand, SpawnGun.OnFire, SpawnablesPanelView.PopulateMenu, PoolSpawner.SpawnMuzzleFlare, PlayerInventory.CheckAmmo (postfix, Infinite Reserve Ammo), LevelsPanelView.CalculateSceneList/SelectItem, SLZ_BodyBlender.AutoFillBones and SLZ_BodyBlender.Brett (prefix returns false), Data_Manager.RELOADSCENE/SAVESPOTCHECKPOINT, LogSupport.Warning.
- Mag-insert event: the game fires MagazineSocket.OnPlugLocked when a mag locks. ShellLoadingController postfixes it. Polling alternatives are Magazine.isMagazineInserted and MagazineSocket.hasMagazine. No mod changes the mag-insert animation or hand pose. Confirmed from code.
- Ammo model (confirmed): ammo lives in PlayerInventory as one pool per Weight class (_lightAmmo, _mediumAmmo, _heavyAmmo) with AddAmmo, RemoveAmmo, GetAmmo, CheckAmmo. A mag carries its own _ammoCount, and magazineData.weight decides which pool it draws from. RegisterMagazine tracks the mags the player owns.
- Has-ammo test (inferred from code): GunFireModes and MultipleFirePoints both stop firing when gun.overrideMagazine == null && chamberedCartridge == null && (!magazineSocket.hasMagazine || magazineSocket.GetMagazine().GetAmmoCount() == 0). So a non-null overrideMagazine is an infinite-ammo flag. InfiniteAmmoGuns sets overrideMagazine on a cloned gun. The Infinite Reserve Ammo mod instead forces the three pools to 500000 after each CheckAmmo.
- Mag-from-pouch swap (AmmoPouchGrabbing, confirmed): on AmmoPouch.OnSpawnGrab the mod compares the grabbed mag's magazineData.spawnableObject.title with the one the other-hand gun needs. If they differ it instantiates the needed mag prefab, RegisterMagazine, sets IsAmmoClaimed, aligns the mag so grip.targetTransform's local offset sits on hand.palmPositionTransform, rotates it to GetRotatedGripTargetTransformWorld(hand), destroys the original, and calls grip.Snatch(hand, isQuick: true). This is the game's own way to place a grip in the hand without a visible jump.
- Mag eject (BetterMagEject, confirmed): two triggers. (a) A 0.15s-stepped coroutine checks each hand's gun and ejects when chamberedCartridge is null and the mag is empty. (b) Menu-button quick taps are counted (release within 0.2s, count resets 0.5s after the last press), and at pressesToEjectMag taps it calls magazineSocket.EjectMagazine(). Per-gun overrides come from MagEjectSettings through HashSets.
- Shell-feed trick (ShellLoadingController, confirmed): a magazine socket is repurposed as a counter. The plug locking adds a shell, the magazine is hidden and immediately ejected, and PullCartridge is blocked at zero shells. Gun.PlayAnimationState(SLIDELOCKED) is used when empty.
- Hand pose detection (BoneMenu MenuManager.OnUpdate, confirmed): open pose = palm.up dot worldUp in (0, 0.6), palm.forward dot head.forward in (0.5, 1), and thumb-out test dot(head.right, palm.up) < -0.8 for left or > 0.8 for right. It requires both hands. Close pose = palm pointing down plus the opposite thumb test. Closing needs 0.1s of the close pose (hysteresis). All timing uses Time.unscaledTime. This is the only gesture recognition in the set and the closest analogue to a thumb-away check.
- Pose and grip API (game, confirmed names): Grip.handPose, SetHandPose(hand, pose), RemoveHandPose(hand), GetHandPose(hand), GetHandPoseTarget(hand). BoxGrip has sandwich, edge, corner, and face HandPose fields. AdManager finds HandPose assets by name through Resources.FindObjectsOfTypeAll<HandPose>() and assigns them. So grab poses are assets assigned per grip, not bones animated in code. PumpSlideGrip and SlideGrip hold normalHandPose and flippedHandPose with SelectHandPose(hand) and a slideBlend float (PumpSlideGrip), which is the game's own blend between two poses.
- Animation and fade API (game, confirmed names; behaviour inferred): Gun has coroutines CoPlayAnimation (fields duration, startPerc, isReversed, state, curve), CoOnAnimationComplete, and CoBlinkHighlight. Reverse is a flag (SLIDEPULL vs SLIDEPULLREVERSED), not a separate clip. GunGrip has FireCycleState {EMPTY, CHAMBER, FIRE, EJECT}, slideGrip, slideCurve (CurveData wrapping an AnimationCurve), and percForNextState. Inference: slide progress is mapped through slideCurve and the state advances when percForNextState is passed. Fade helpers exist too: GunOptionSelect.CoFade (material or text, targetOpacity, duration), CoFadeToColor, InteractableIcon.CoBlendIconScaleFromTo, and VirtualController.positionBlend/rotationBlend.
- Pump-slide fix (GunSlideFixes, confirmed): a round chambered means PumpSlideGrip.slideDistance is zeroed during OnSlideRelease. It is restored after firing and on grab, so the pump locks while loaded. Gun.isFiring is cleared on a slide grab (not for burst).
- Burst and charge (GunFireModes and SimpleGunModifiers, confirmed): burst calls gun.Fire() repeatedly from Update while shouldFire, counts shots in OnPostFireGun, and blocks re-fire via gun._isSlideGrabbed for 0.2s. Charge-to-fire holds PreFireGun false until hand.controller.GetPrimaryInteractionButton() has been held for chargingTime. Dry-fire via GunSFX.DryFire() is the feedback.
- Custom items: ItemLoading reads .melon asset bundles from UserData/CustomItems (MD5 hash for reloads). The bundle's CustomItems GameObject has a LocalizedText key holding ItemSettings JSON. Each child becomes a SpawnableObject (CreateSpawnableObject, then PoolManager.RegisterPool, then SpawnMenu.AddItem). Shaders named SDK/* or Standard are remapped to SLZ/* or Valve/vr_standard.
- Per-gun config without code: (a) CustomMonoBehaviourHandler stores field values as JSON in LocalizedText keys (CUSTOM_MONOBEHAVIOUR-::-Type-::-json) and applies them with reflection on Awake. (b) FieldInjector makes real serialized fields on IL2CPP classes, with compiled Expression-tree serializers in the ISerializationCallbackReceiver vtable. (c) Naming conventions: 'FirePoint (n)', 'BurstFire/3', 'AngleVariation/5', 'MultipleFirePoints' child objects.
- Cross-mod hooks: Stats finds the Custom Maps MelonMod and attaches to its static OnCustomMapLoad event by reflection (EventInfo.AddEventHandler). CustomMaps subscribes to SpawnMenu.OnItemAddedToMenu. BoneworksModdingToolkit.BoneHook is an [Obsolete] forwarding layer kept for old mods.
- Embedded code: ItemLoading.LoadAssemblyFromMelon calls Assembly.Load on a 'ModAssembly' asset found inside a .melon bundle, logs a [NOTICE] that it contains executable code, writes the DLL to UserData/ExportedAssemblies, and instantiates any EmbeddedMod subclass. Defaults: allowEmbeddedCode = true, exportEmbeddedAssemblies = true. Worth knowing before installing third-party .melon files.
- Outbound network (confirmed in code): Stats.ReportStats GETs stats.extraes.xyz on startup (version, bonemenu mode, feature flags; custom map names when a custom map loads) unless DisableStats is set (default false). VersionChecking GETs boneworks.thunderstore.io/api/v1/package/. AdManager (HappyFunTime, off by default) fetches random images from dog.ceo/api.
- Scene and startup order (Main.cs): Preferences.Initialize, BackwardsCompatibility, Hooking.SetHarmony, WarningSilencers, Hooking.InitHooks, HookingHelpers.Setup, SpawnMenu.HookPopulateSpawnMenu, then the feature Setup() calls, then MenuManager.InitialSetup. OnSceneWasInitialized runs Player.FindObjectReferences and the first-level .melon load. OnUpdate drives BetterMagEject, MenuManager, and Notifications every frame.
- Limits of this analysis: the decompiled game files are interop stubs. The mag-slide gesture logic, the double-reload timing, and pose blend curves are not in them, so the thresholds and timings above are only what the mods use, not what the official game does. The mods are the only source of concrete numbers.

LESSONS
- Thumb-away detection: reuse the BoneMenu approach. Compute dot(head.right, palm.up) and gate with a threshold (about 0.8 in the mod), then require the state to hold for a short time (0.1s in the mod) before switching. This gives a clean thumb-slides-away trigger for the push phase without flicker.
- Prototype the push as a two-pose blend: keep a normal and a flipped (or pushed) HandPose, drive a 0-1 blend value the way PumpSlideGrip.slideBlend does, and switch the grip's pose through the game's SetHandPose/RemoveHandPose path rather than moving bones by hand.
- For the grab pose (image 3), assign a HandPose asset to the mag's Grip and use the same snap math as AmmoPouchGrabbing: place the mag so grip.targetTransform's local offset sits on palm.position, rotate with GetRotatedGripTargetTransformWorld(hand), then Snatch(hand, isQuick: true). This avoids a visible jump when the mag is grabbed.
- Double-mag reload as a double tap: copy the BetterMagEject pattern (count taps only when released within about 0.2s, reset the count about 0.5s after the last press). Keep the pose state separate from the tap counter so that a single reload pose is never mistaken for a double.
- Fade-in and fade-out between poses: follow the game's own pattern of a coroutine with duration, startPerc, isReversed, and an AnimationCurve (see Gun.CoPlayAnimation and CurveData). Fade-out is the same curve played in reverse, not a second clip. Use time-based interpolation (dt-scaled), not the fixed 0.8 per-frame Lerp used in BoneMenu, so the fade is frame-rate independent.
- Expose every threshold (thumb dot cutoff, hysteresis time, tap windows, blend duration) as a MelonPreferences entry with a ModPref-style wrapper, and add a BoneMenu-style in-VR menu to tune them. The mod's Preferences and DefaultMenu show this works well for tuning gestures on the headset.
- Hook the mag lock event instead of polling: ShellLoadingController shows that MagazineSocket.OnPlugLocked (postfix) is the reliable 'mag just seated' moment. Use it to trigger the slide-release or chamber animation at the right time.
- Keep ammo data on the mag and the pool on the player: magazineData.weight decides the pool, PlayerInventory owns the counts, and Magazine.IsAmmoClaimed plus RegisterMagazine stop double counting. Follow that split for any custom reload logic.
- Architecture: a single hooking facade (Hooking) that wraps the patches, gives each mod its own Harmony instance, and forwards to events is a clean base for a VR mod. It also makes unpatching per feature possible.
- Data-driven per-gun settings: the JSON-in-LocalizedText approach (CustomMonoBehaviourHandler) or child-name conventions (MultipleFirePoints) let the user tune each pistol's gesture without code. Start with the naming-convention approach if the project has no bundle pipeline.
