Verification of the 2026-10-16 reload changes (rockets, pistol magazines, hand poses): 5 read-only Haiku reviewers,
each critical/major finding checked by a skeptic told to refute it.

[major] src/Weapons/WeaponAnalyzer.cs:2152  Static launcher hand copy shows every warhead after a shot  ->  refuted (geometry)
  trigger: A launcher with extra warheads hidden by MeshRenderer.enabled = false (RPG-7V style) whose analysis fell back to the static pose (WeaponAnalyzer notes contain 'static', or the 'no animator' warning). Fire it, then take a spare rocket from the pouch while the launcher is empty: the rocket in hand shows all five warheads.
  change:  Require the renderer's own state at analysis: 'if (r.enabled && !(r is ParticleSystemRenderer) && sampler.IdleVisible(r.transform))'. The sampled path already implies this, so only un-sampled weapons change. Add an autotest: a static launcher with one warhead renderer.enabled = false, check after a shot that the hand copy holds one warhead.
  verdict: The static-branch gap is real but the stated in-game trigger is not reached. The gap: WeaponAnalyzer.cs:2152 tests only `sampler.IdleVisible(r.transform)`, and PoseSampler.cs:531 sets `_idleVisible[i] = WeaponAnalyzer.ActiveUpTo(t, _liveRoot)`, which checks `activeSelf` only, so a warhead with MeshRenderer.enabled=false is stored in MagShownAtIdle. MagazineProp.cs:671 then lets it through when anyShown is false. But that branch runs only when `sampled` is false. WeaponAnalyzer.cs:3183 sets `sampled = canSample && sampler.Run(...)`, and canSample (WeaponAnalyzer.cs:481) needs an animator with a controller on the weapon's own root. The game sets `animator = GetComponent<Animator>()` on the same object and nulls it when there is no controller (Weapon.cs:616-620). RPG-7V variants play their own reload animation and fire animation events (AutoTest.cs:2993, TurretAim.cs:81), so they take the sampled branch. There PoseSampler.cs:444-445 (Visible) reads `r.enabled`, so disabled warheads are excluded, which is what commit 96667e6 intends. The static fallback needs an inherited parent animator (WeaponAnalyzer.cs:492-495), a clone hierarchy count mismatch (PoseSampler.cs:296-299), or a sampler exception (PoseSampler.cs:174-177). None is shown for an RPG-7V. Also, the mod never disables magazine renderers on fire (HeldWeapon.cs:1927 hides magazines by localScale), so the all-hidden state the trigger needs must come from game animation, which a no-animator weapon does not get. Latent only: adding `r.enabled` at WeaponAnalyzer.cs:2152 would close it.

[major] src/Weapons/MagazineProp.cs:430  Unmeasured tube falls back to muzzle point; bad depth keeps short rail  ->  refuted (geometry)
  trigger: A launcher whose tube is a SkinnedMeshRenderer. Hold the rocket's tail at the real mouth: it is X cm behind the entry, X being the gap from the muzzle point to the mouth. The strict test needs along > -0.03 (ReloadInteractions.cs:1080) and the loose test -0.12 (LooselyLined, line 1180). For X above about 11 cm the rocket can never be lined up at the mouth; below that only the loose grab takes it, with a snap (see the ReloadInteractions finding).
  change:  When TubeFront finds no MeshFilter, measure the skinned launcher meshes instead (SkinnedMeshRenderer.BakeMesh, or localBounds corners through smr.transform into gun space). If nothing is measurable, do not use the muzzle point: take the seated nose, mouth = Vector3.Dot(tailSeated, aim) + Mathf.Abs(Vector3.Dot(prop.TipLocal - prop.BaseLocal, prop.InsertDirLocal)), since a rocket that fills the tube has its nose at the mouth. Replace the silent constructor fallback with a warning and an explicit decision, not the old 0.1-0.3 m length.
  verdict: Refuted as stated. Both halves are misdescribed in mechanism or magnitude, and the trigger is not shown at HEAD.

1) The 11 cm "can never line up" result comes from a sign error. MagazineProp.cs:428-429 sets `float mouth = tube ? front : Vector3.Dot(d.MuzzlePoint, aim); float depth = mouth - Vector3.Dot(tailSeated, aim);`, and line 432 sets RailLength = depth + 0.01. The entry is tail + aim*RailLength, which is muzzle + 1 cm, so it sits in front of the real mouth. RailPose (MagazineProp.cs:1589, `seat.position - insert * (RailLength - RailDepth)`) and HandAlongRail (ReloadInteractions.cs:1191-1194) use insert = -aim, so along = entry_aim - tail_aim. A tail held at the real mouth (aim coordinate muzzle - X) gives along = X + 0.01 > 0, which is inside the rail. The strict test at ReloadInteractions.cs:1080 (`along > -0.03f && along < prop.RailLength`) passes for any X below the true depth. The earlier review at reports/agents/review85-2026-10-16/regress_ammo-mags.txt:16-17 reached the same conclusion (lined up, drawn too far out) and rated it minor and unverified.

2) The bad-depth branch (line 430, `if (depth > 0.05f && depth < 1.2f)`) is real code, and Log.InfoOnce at line 434 does report it. The stated effect is wrong. For depth above 1.2 m the entry sits (depth - C) inside the mouth, about 0.9 m or more, not 10-30 cm. For depth at or below 0.05 m it sits at least 5 cm in front. The trigger is the depth value itself, not a skinned tube. TubeFront (MagazineProp.cs:866-890) returns false only when GunBody is null or has no qualifying static MeshFilter. A skinned tube that has any static part therefore measures that part instead of falling back.

The repo's only evidence for depth above 1.2 m is reports/shots/film-previous/game-log.txt:99 (RPG-7, muzzle to tail 144 cm, rail left at 24 cm) and reports/shots/film-previous/autotest.txt:41 ("lined up -121 cm behind the muzzle (NOT AT THE MUZZLE)"). git log -S shows the 1.2 guard came in aa03500 and the tube-front measurement in 96667e6, so that run predates the tube-front change and does not establish the trigger at HEAD. Whether the RPG-7 measures above 1.2 m at HEAD depends on the tube front, which the code cannot settle. This is the live risk to film at HEAD on an RPG-7, but the claimed skinned-tube mechanism and the 11 cm threshold are not supported by the code.

[major] src/Weapons/MagazineProp.cs:1321  Pistol magazine pulled out by hand snaps into the palm-push pose  ->  HELD UP (regress)
  trigger: Manual reload. The off hand grabs a seated pistol magazine and pulls it out (PullSeatedMagazine, ReloadInteractions.cs:523-542, sets FromSeat=true at 536). About 1.5 cm out FromSeat clears. On a pistol magazine (rail about 4 cm) RailDepth/RailLength is then about 0.6, so push is about 0.85 after smoothing. The glove snaps to PushPalm (palm under the base plate, pushing up into the gun) and HandModel.PushBlend opens the fingers and lifts the thumb, while the magazine is being drawn out. It only relaxes back to the fist near 3 cm out. The palm push is meant for seating only.
  change:  Gate the push on the direction of travel, not on depth alone. Keep a flag that is set on inward motion (goingIn at ReloadInteractions.cs:1138) and cleared on outward motion (RailDepth below PrevDepth), and use it at MagazineProp.cs:1321 in place of the depth-only term. A magazine that has been pulled out keeps the fist.
  verdict: The claim holds. Nothing in the code gates the palm push on direction of travel, and the direction that is computed is never stored on the prop.

Code path:
- ReloadInteractions.cs:523-542 (PullSeatedMagazine): RailDepth = RailLength, RailHandOffset = HandAlongRail - RailLength, and `prop.FromSeat = true;` at line 536. FromSeat is only ever set true here.
- Each frame in the on-rail branch of UpdateHeldProp, the pull-out moves RailDepth to RailLength - pullDistance (lines 1123-1133). Lines 1134-1136 read `if (prop.FromSeat && prop.RailDepth < prop.RailLength - 0.015f) prop.FromSeat = false;`. This fires after 1.5 cm of travel in either direction, and FromSeat stays false after that.
- Line 1138 `bool goingIn = ...` is a local. It is not saved to the prop, so ShowOnRail cannot see the direction.
- ShowOnRail is called every frame from BeforeRender (ReloadInteractions.cs:1717). OnRail stays true during a short pull-out (the check at line 1124 only drops it at about 3 cm or on lateral drift).
- MagazineProp.cs:1321: `float push = PistolSized && !FromSeat && RailLength > 1e-4f ? Mathf.InverseLerp(0.2f, 0.75f, RailDepth / RailLength) : 0f;`. Once FromSeat clears, nothing in this expression depends on direction.

Magnitude: RailLength = Clamp(extent * 0.9, 0.03, 0.09) (MagazineProp.cs:183), so the minimum is 3 cm. At 1.5 cm out the ratio is 1 - 0.015/L. For L = 0.04 that is 0.625, which gives push about 0.87 after the smoothstep at line 1324. For the 3 cm minimum it is about 0.57. The blend is therefore strong from the moment it starts, and only falls to near zero around 3 cm out. The claim's 4 cm example is representative.

Timing: HandModel.cs:650-651 eases _push toward PushBlend over 0.12 s, and HeldPalm eases over 0.08 s (HandModel.cs:566). So it is a fast ease of about 0.1 s, not a literal single-frame snap.

Intent mismatch: the comment at MagazineProp.cs:1319 says "A pistol magazine going in", and the comment at ReloadInteractions.cs:1136 assumes FromSeat clears when it is "pushed back". The code clears it on any 1.5 cm of travel.

In-game trigger: manual reload only (the `Manual` gate at ReloadInteractions.cs:250). The off hand squeezes within radius*1.1 of SeatedMagBaseWorld on a seated pistol magazine (choice 6 at line 336), then pulls it out. The glove moves to the palm-under-base pose and the fingers open and the thumb lifts while the magazine is still being drawn out, relaxing back to the fist around 2-3 cm out.

Precise change: store the direction and gate the push on it. Add a `public bool GoingIn` to MagazineProp, set it at ReloadInteractions.cs:1138 (`prop.GoingIn = goingIn;`), clear it in the FromSeat and OnRail-off branches, and change line 1321 to `PistolSized && !FromSeat && GoingIn && RailLength > 1e-4f ? ...`. If a hand that stops mid-insert should keep the palm, latch the flag on when goingIn and clear it only when the depth decreases.
