#2 [major] [confidence medium] Steering wheel or flight stick stays locked when the grabbing hand loses tracking mid-grip
   where: src/Rig/CockpitControls.cs:113-116 (UpdateHand returns when !hand.Tracked, before the release checks at :142-147 and :169-176); steering published at :76; stick deflection published at :183
   trigger: The player grips the wheel or stick, then that controller goes untracked: powered off, battery dead, or dropped out of the headset view. The grip is released while untracked, or the controller simply stays untracked.
   effect: UpdateHand never runs for that hand while it is untracked, so _onWheel[i] or _stickHand stays set and hand.Role stays HandRole.Cockpit. VehicleInput.WheelSteer keeps the last steering value and VehicleInput.FlightStick the last deflection, so the vehicle keeps turning or pitching and rolling until the controller reports tracked again. The release is only processed on the first tracked frame; only ReleaseAll (seat change, menu, vehicle gone) clears it earlier.
   evidence: VRHand.Tracked = raw.valid (VRHand.cs:69-75, :84-85), so an untracked controller sets Tracked false while Held is still refreshed from bState (VRInput.cs:221-226). CockpitControls never reads GrabHeld on that frame because of the early return. Holding the lock while the grip stays closed is intended; the bug is that a release during the untracked period is never acted on.
   fix idea: Process the release before the Tracked check (GrabHeld does not need a pose), or on tracking loss run the same release path for that hand (clear _onWheel/_stickHand and ease steering or deflection to zero).

#3 [minor] [confidence low] Ground check sphere cast holds only 64 hits, so a pile of loose bodies can hide the ground
   where: src/Rig/GroundCheck.cs:22 (Hits = new RaycastHit[64]), :55 (SphereCastNonAlloc), :59-77 (loop over the buffer)
   trigger: 64 or more colliders overlap the hips sweep, e.g. a pile of light dynamic bodies (cases, dropped props, ragdoll limbs) under the feet. Unverified in practice; it depends on how many such bodies accumulate.
   effect: SphereCastNonAlloc fills the buffer in unspecified order and discards the rest. If the ground is among the discarded hits, Cast returns false and FirstPersonController treats the player as airborne until the pile shrinks.
   evidence: GroundCheck.cs:21 comment acknowledges the hits are unsorted; the NonAlloc buffer limit is documented Unity behaviour. The replaced call matches the decompiled game's Ray-based SphereCast form used by the patch, so the patch itself is correctly targeted.
   fix idea: Use a larger buffer, or a second cast masked to ground layers so light loose bodies never take slots from the ground.
