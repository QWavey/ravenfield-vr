[major/high] src/Input/GameInputBridge.cs:216  Seat exit completes with no confirming haptic
  what:   HeldToLeaveSeat: `float t = (Time.unscaledTime - _leaveHeldSince) / LeaveSeatHold; if (t >= 1f) { return true; }` (lines 216-219) runs before the tick haptic. The tick haptic (lines 220-225) only fires for t < 1, so ticks 1..4 land at t=0.2/0.4/0.6/0.8 s and the hold completes silently. A grep of src/ shows the only haptic on this path is line 224.
  why:    A seated player feels four buzzes, the last one about 0.2 s before the exit, then is ejected with no pulse at the moment it happens. Hold-to-exit is the one interaction here whose feedback stops short of its result.
  change: Immediately before the `return true` at line 218, add `if (_leaveTicks < 5) { _leaveTicks = 5; hand?.Haptic(0.08f, 160f, 0.9f); }`. The reset at line 213 gives one pulse per hold. Keep the tick loop as it is.

[minor/low] src/Input/GameInputBridge.cs:179  Second lower-button press opens the menu silently and swallows a slide release
  what:   On a second lower-face press within 0.4 s, `VRInput.Consume(DigitalAction.SlideRelease, hand)` (line 179) and `Consume(Squad)` (line 180) run, and `open = true` raises TogglePauseMenu (line 107). Nothing signals the menu opening.
  why:    A deliberate second slide release within 0.4 s opens the pause menu mid-fight, and that release is lost. Nothing in the hand says the menu opened, so the player cannot tell why the view changed. How often this happens depends on how players rack slides, so confidence is low.
  change: Add a pulse when the menu opens, for example `VRInput.Haptic(hand, 0.03f, 160f, 0.5f)` in the `open = true` branch at line 181. Decide whether the second slide release should still count (line 179); if it should, stop consuming SlideRelease there and keep only the Squad consume.

[minor/medium] src/Input/GameInputBridge.cs:309  Sprint, stance and scope toggles give no haptic
  what:   The sprint toggle (lines 309-318, `SprintActive = !SprintActive`), the stick-flick crouch and prone toggles (lines 378-396), and the magnifier tap and NextScope set (lines 252-259) call no haptic. Add `VRInput.Haptic(VRInput.GunHand, 0.02f, 200f, 0.5f)` after the magnifier tap (line 254) and the NextScope set (line 259), matching WeaponSystem.cs:475.

[minor/medium] src/Input/TurretAim.cs:22  Turret aims with the settings hand, not the gun hand
  what:   Hand mode uses `rig.SetDominant.Tracked` (line 22) and `rig.SetDominant.Pointer.Forward` (line 24). `SetDominant` is `Hands[(int)VRInput.Dominant]` (src/Rig/VRRig.cs:64), the handedness setting. The turret's trigger comes from `VRInput.GunHand` (GameInputBridge.cs:102 and 121).
  why:    After a weapon is passed to the off hand (VRInput.cs:617 GunHandSwapped), the turret is aimed by the hand that is not on the trigger. The player fires with one hand and steers with the other.
  change: Replace `rig.SetDominant` with `rig.Hand(VRInput.GunHand)` on lines 22 and 24. VRRig.Hand(Hand) already exists at VRRig.cs:65.

[minor/low] src/Input/TurretAim.cs:49  Turret slew is per rendered frame, so VR turn speed depends on frame rate
  what:   Steer returns `Mathf.Clamp(yaw * gain, ...)` (line 49), a fixed amount per call. The game adds that amount in Update with no Time.deltaTime: `localEulerAngles.y += vector.x` (MountedTurret.cs:96-103; TankTurret.cs:25-33; MountedStabilizedTurret.cs:195-200).
  why:    Turret speed per second scales with the render rate. A 120 Hz headset, or reprojection dropping to 45 Hz, makes the same error turn the turret at a different speed than the 60 fps tuning. The game's AI path has the same dependency (MountedTurret.cs:131-132), so this is not a clear VR-only bug.
  change: Scale the result inside Steer by `Time.deltaTime * 60f`, which keeps the 60 fps feel and makes slew independent of frame rate. Check it against the game's own feel before shipping.

[minor/medium] src/Input/TurretAim.cs:58  Turret steer gains ignore per-turret sensitivity fields
  what:   Steering uses fixed gains per patch class: `Steer(__instance, ..., 5f, 10f, ...)` (line 58), `3f, 10f` for TankTurret (line 65), `5f, 3f` for MountedStabilizedTurret (line 72). The game's human aim path scales input by each turret's public `sensitivityX`/`sensitivityY` (MountedTurret.cs:129 with fields at lines 33 and 35; MountedStabilizedTurret.cs:73/75; TankTurret.cs:7/9). The AI path does not (MountedTurret.cs:131-132 uses a constant 5).
  why:    In VR every turret slews at the same rate, whatever the designer set. A turret with sensitivity below 1 is faster in VR than in flat play. The effect depends on prefab values, which are not in the repo, and is zero where they are 1.
  change: Pass the turret's sensitivity into Steer as separate yaw and pitch multipliers. Multiply yaw by sensitivityX and pitch by sensitivityY, matching the mapping at MountedTurret.cs:129, so the gains at lines 58/65/72 become base * sensitivity per axis.
