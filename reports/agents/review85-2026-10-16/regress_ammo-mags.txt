[major/medium] src/Weapons/MagazineProp.cs:382  Rocket rail runs along an oblique insert but its depth is measured along the bore
  what:   Axes() keeps the eject-axis insert unless the test fails: `if (Vector3.Dot(insertGun.normalized, -d.AimAxis.normalized) < 0.7f) { insertGun = -d.AimAxis.normalized; }` (line 382). Create() then measures the rail along the bore (line 431, changed in 96667e6 from `Vector3.Dot(tailSeated - d.MuzzlePoint, insertGun.normalized)`): `float depth = mouth - Vector3.Dot(tailSeated, aim);`. RailPose, HandAlongRail and LooselyLined move the tail along InsertDirLocal (the oblique insert), so the two disagree whenever the eject axis is 16 to 45 degrees off the bore.
  why:    Let c = dot(insert, -bore) in [0.7, 0.96). The rail's depth-0 point then sits (1-c)*RailLength behind the tube front: about 23 cm at c=0.7 for an RPG-7-sized rail (~0.75 m). A tail held at the tube front reads about -0.16 m along the rail at 45 degrees, outside the strict window (ReloadInteractions.cs:1080, along > -0.03) and, beyond about 37 degrees, outside the loose window (ReloadInteractions.cs:1177, along > -0.12): the rocket at the muzzle is refused, the case aa03500 and 96667e6 set out to fix. Inside the loose window it is taken and drawn about 16 cm further in. This also contradicts aa03500's 'it always goes in back along the bore'. Unverified: depends on the MagEjectAxis the analysis produces for each launcher (printed as eject= by WeaponRig.cs:234).
  change: Drop the 0.7 test for rockets in Axes(): `if (kind == PropKind.Rocket) { insertGun = -d.AimAxis.normalized; frontGun = d.Up; }`. Then the insert, rail, depth, TipLocal/BaseLocal and the pouch copy (BuildDisplay shares Axes) all use the bore. If an oblique first motion must be kept, measure depth along insertGun from the tube-front point instead of along aim.

[minor/medium] src/Weapons/MagazineProp.cs:286  Grip halves and the pistol/box class change after the first hold, so the pose pops
  what:   MeasureSectionFromVolume() writes _frontHalf, _sideHalf and CrossHalf (lines 285-286) after construction. It runs from ShapeHand() (line 1147) in the same frame FollowHand() computes HoldPose (the rest offset at line 1026, gripAt at 1017, box offset at 1034). PistolSized and BoxSized (lines 66, 74) also select the hand pose (HandPoses.cs:165-171). FollowHand (lines 1351-1368) only eases when Attach set _attachAt (line 985), which a fresh magazine does not do.
  why:    For the first magazine(s) of a weapon type whose meshes were unreadable at construction (GripSection returns false, so the box was used), the magazine and glove jump in the frame the volume becomes Ready, and the rifle/pistol/box pose can switch with it. Later magazines of that type start from the cached GripSections values, so the effect is limited to the first held ones.
  change: When MeasureSectionFromVolume changes the halves while the prop is held, re-base the ease: set `_attachFrom = RigidPose.Of(Go.transform); _attachAt = Time.unscaledTime;` before the new pose is used (the same mechanism Attach uses), or keep the box-based pose until _volume.Ready and then ease from it.

[minor/low] src/Weapons/MagazineProp.cs:430  Skinned-tube launcher falls back to the muzzle point the commit says is past the warhead
  what:   `float mouth = tube ? front : Vector3.Dot(d.MuzzlePoint, aim);` When TubeFront finds no mesh of its own (line 858: 'False when it has no mesh of its own to measure (a skinned tube)'), the mouth is MuzzlePoint. Lines 425-426 say that point is 'in front of the grip on an RPG-7, past the warhead'.
  why:    On any launcher whose tube is a skinned mesh, the rail still ends at the projectile start, which is past the tube's front, so the rocket is lined up and drawn too far out: the error 96667e6 was written to fix. Only matters if such a launcher exists; not verified.
  change: On fallback, measure the front from the non-magazine SkinnedMeshRenderer bounds projected on aim (excluding MagazineParts) before using MuzzlePoint, and log which source was used.

[minor/medium] src/Weapons/ReloadInteractions.cs:1254  CrossHalf is now the grip band, but strike reach, push reach and eject offset still read it as the base plate
  what:   2467c07 made CrossHalf the grip-band size: `CrossHalf = Mathf.Clamp(Mathf.Max(frontBox, sideBox), ...)` after `frontBox = frontGrip` (MagazineProp.cs:166-171), and again in MeasureSectionFromVolume (line 286). The field's doc still says 'how big its base plate is' (line 63). Callers: `float strikeReach = Mathf.Clamp(prop.CrossHalf * 2f + 0.025f, 0.06f, 0.13f);` (line 1254, comment: 'a strike lands anywhere on the old base plate (as wide as the magazine)'), `float pushReach = Mathf.Clamp(prop.CrossHalf + 0.025f, 0.035f, 0.08f);` (line 1255), and `float width = Mathf.Max(0.02f, old.CrossHalf * 2f);` (line 1337, the ejected magazine's offset).
  why:    For magazines whose base plate is wider than the grip band (the commit's own examples: AUTOMATICO 4.8 cm, FNX-45 6.5 cm), strikeReach shrinks toward its 6 cm floor and the ejected magazine is offset by its body width, not its base plate. Seating a wide-base pistol magazine by its base gets harder, and an ejected one can land closer to the receiver than its base is wide.
  change: Keep the box-based half size as its own property: compute `BaseHalf = Mathf.Max(frontBox, sideBox)` in the constructor before `frontBox = frontGrip` (MagazineProp.cs:158-171) and not overwritten in MeasureSectionFromVolume. Use BaseHalf at ReloadInteractions.cs:1254, 1255 and 1337. Keep CrossHalf (grip band) for PistolSized, BoxSized and the hold. Correct the doc comment at MagazineProp.cs:63.
