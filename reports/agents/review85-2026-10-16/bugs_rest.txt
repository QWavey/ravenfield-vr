[major/high] src/Weapons/DrivingWeapons.cs:28  Car and Humvee drivers can never draw: the car horn counts as a mounted weapon
  what:   CanDraw returns false when `seat.HasAnyMountedWeapons()` (lines 28-31: `if (seat.HasAnyMountedWeapons()) { return false; }`). Seat.HasAnyMountedWeapons() is `weapons.Length != 0` (decompiled Seat.cs:214-217). The car horn is a MountedWeapon (CarHorn : MountedWeapon) stored in that same array: Actor.EnterSeat unholsters `seat.weapons[0]` for any seat with mounted weapons (decompiled Actor.cs:2534-2536), AiActorController.cs:1913 reads a car driver's `seat.activeWeapon` as CarHorn, and MountedWeapon.Unholster (MountedWeapon.cs:167) is the only place that sets `seat.activeWeapon = this`, so the horn must be an element of seat.weapons. The prefab array itself cannot be read here, so this link is inferred from that code.
  why:    For any car or Humvee driver seat, CanDraw returns false every frame. UpdateDrivingWeapons (WeaponSystem.cs:505-511) then calls DrivingWeapons.Reset and the holster grab never draws. The feature documented in README.md:112 and marked done in Tasks.md:167 only works in passenger seats with no mounted weapon. The mod's own code assumes cars carry the horn: PutAway (DrivingWeapons.cs:53-55) restores `seat.weapons[0]` for seats with mounted weapons, and GameContext.SeatKind classifies Car, ArcadeCar and Tank driver seats as Ground before it looks at mounted weapons. No autotest drives vehicles (changed.md:1250), so this path was never exercised.
  change: Gate on guns only: replace the check with `if (seat.weapons.Any(w => w != null && !(w is CarHorn))) { return false; }` (add `using System.Linq;`). Keep the IsDriverSeat / Car / ArcadeCar rule as is. In PutAway, restore the horn by type (the seat.weapons entry that is a CarHorn) instead of `seat.weapons[0]`, so the horn comes back even if a seat lists it later.

[minor/low] src/Core/InstallCheck.cs:60  Runtime install reports success without verifying the copies
  what:   The copy loop skips any `<name>.bin` that is missing from the bundle (lines 46-54), and the manifest copy is skipped if the bundled manifest is absent (lines 55-59). Line 60 still returns "Installed the OpenVR runtime into ravenfield_Data. ... restart Ravenfield". VRPlugin.cs:33 then logs that string with Log.Error.
  why:    If the shipped runtime bundle is incomplete, every launch reports "installed, restart", the next launch finds the same files missing, and VR never starts. The success line also appears in the error log, so the cause is hard to see. The shipped build (build.ps1:146-149) copies all x64 DLLs and the manifest, so this needs a broken bundle to trigger.
  change: After the copy, re-run the `missing` check over NativeFiles and the manifest. Return the restart message only when everything exists; otherwise return the "missing" message naming the absent files. Log the success text at Info level.

[minor/high] src/Weapons/BodyZones.cs:49  Looking straight down flips the torso yaw by about 145 degrees
  what:   When the flattened forward is nearly zero (`if (f.sqrMagnitude < 1e-4f) { f = head.up * -1f; ... }`, lines 47-51), the fallback uses -head.up. When the head points straight down, head.up is the horizontal forward direction, so -head.up points backward. The fallback is only correct when looking up.
  why:    On the frame the head passes about 89.4 degrees down, headYaw is 180 degrees wrong. The clamp at lines 59-62 then moves _torsoYaw by about 145 degrees in one frame, so every holster and the pouch swing to the other side of the body. After the head comes back up, the torso is still 35 degrees off and takes about 1.4 s (25 deg/s from line 64) to settle.
  change: Use the up vector that matches the pitch direction: `f = head.forward.y < 0f ? head.up : -head.up;`, with the existing zero-length guard kept.

[minor/high] src/Weapons/VRScope.cs:262  Measured-scope lens FOV assumes 9 cm eye relief; real distance is 7.8 cm
  what:   `float lensAngle = 2f * Mathf.Atan(_radius / EyeRelief) * Mathf.Rad2Deg;` with the constant EyeRelief = 0.09f (line 17). For a measured scope model the lens is placed at `ScopeOcular - EyeDirection * 0.002f` (line 55), while the eye point is `ocular - AimAxis * ScopeEyeRelief` with ScopeEyeRelief = 0.08f (WeaponAnalyzer.cs:817 and 881). The real eye-to-lens distance is therefore about 0.078 m. The non-model lens (line 56, and the SightLine constructor at line 65) is consistent because it is placed at EyePoint + dir * EyeRelief.
  why:    The camera FOV is lensAngle / magnification, so the lens's angular size is underestimated by about 13-15%. For a lens radius of 0.015 m the code uses 19.0 degrees where the true angle is 21.8 degrees. Every measured scope therefore draws the world about 15% more magnified than its nominal power.
  change: Compute the real distance once in the private constructor (`_eyeRelief = Vector3.Distance(eyePoint, lensPos)`) and use `_eyeRelief` in place of the EyeRelief constant at line 262.

[tiny/low] src/UI/AnyKeyPrompts.cs:45  Controller skip can call GotoNextScene twice in one frame
  what:   The postfix on GotoMenu.LateUpdate (lines 41-47) calls `__instance.GotoNextScene()` whenever a controller button is pressed. The original LateUpdate (decompiled GotoMenu.cs) already calls it on the 10 s timer or on keyboard anyKeyDown, and the postfix has no guard.
  why:    If the timer or a keyboard key and a controller press land in the same frame, GotoNextScene runs twice. The second call recomputes `GetActiveScene().buildIndex + 1` after the first LoadScene, which can skip a scene. The window is one frame, so this is rare.
  change: Record `Time.frameCount` in a Prefix on GotoMenu.GotoNextScene and return false when it has already run in the current frame, or otherwise make the postfix call run at most once per load.
