[major/medium] src/Core/VRManager.cs:261  Headset-off pause is undone by the game's own UnpauseGame calls
  what:   OnHeadsetWorn pauses with GameManager.PauseGame() and sets _pausedForHeadset = true (VRManager.cs:261-265). Nothing re-asserts the pause afterwards. The game calls GameManager.UnpauseGame() unconditionally in IngameMenuUi.Hide() (IngameMenuUi.cs:40), in GameManager.OnLevelLoaded for any non-additive scene load (GameManager.cs:1727) and in FpsActorController.DisablePhotoMode (FpsActorController.cs:1779). Each sets Time.timeScale = 1 while _pausedForHeadset stays true.
  why:    Headset taken off mid-match, then the game's pause menu is opened and closed (Show pauses, Hide unpauses), or any non-additive scene load happens: the match runs unpaused with no headset on and the player gets shot. The comment at VRManager.cs:253-255 says this must not happen. When the headset goes back on, OnHeadsetWorn(true) sees GameManager.IsPaused() == false and does nothing, so the flag just clears. The keyboard trigger is inferred, not verified: the mod's own pause toggle is controller-only (GameInputBridge.cs:107), so whether flat Escape reaches IngameMenuUi while the headset is off is unconfirmed. The scene-load and photo-mode paths are unaffected by that question.
  change: Re-assert the pause once per frame in VRManager.Update, after PumpEvents() (line 140) and before the Log.Guard calls: if ((_pausedForHeadset || _pausedForDashboard) && GameContext.InGame && GameManager.instance != null && !GameManager.IsPaused()) GameManager.PauseGame(); Because the flags are cleared synchronously inside the event handlers, a worn headset will not re-pause. The same check covers the dashboard flag.

[minor/medium] src/Core/GraphicsPresets.cs:95  Switching the preset to Game restores the VR start-up quality, not the Quality level the game menu holds
  what:   Apply() on the Game branch calls RestoreGameQuality() (lines 95-98), which writes _gameQuality, a snapshot taken once when the first preset applied (lines 157-167). The game's options save sets the level with QualitySettings.SetQualityLevel(GetDropdown(Quality), true) and then calls Apply(false) (Options.cs:298 and 300). That Apply is patched by OptionsApplyPatch (GraphicsPresets.cs:257-266), which then calls GraphicsPresets.Apply() and overwrites the fields the preset sets.
  why:    Launch with Medium (snapshot = the start-up level, e.g. High). Change Quality to Low in the game's Options and save: the Medium preset overrides it. Switch the preset to Game: shadows, AA and LOD go back to the High snapshot while the menu still says Low. This contradicts the VRConfig.Graphics description, 'Game leaves graphics to the game's menu' (VRConfig.cs:151-153), and the intent of commit abcdde0.
  change: Stop snapshotting QualitySettings. Add a static int _gameLevel. In OptionsApplyPatch.Postfix, before GraphicsPresets.Apply(), set _gameLevel = QualitySettings.GetQualityLevel() (SetQualityLevel has already set the menu's level at that point, and presets only change properties, not the level index). Set _gameLevel in ApplyProfile's first-capture branch too. In the Game branch, replace RestoreGameQuality() with QualitySettings.SetQualityLevel(_gameLevel, applyExpensiveChanges: true) and keep _gameLevel = null handling as is.

[minor/low] src/Util/MaterialFix.cs:16  Fixed map keeps every repaired material copy alive for the whole session
  what:   The static Dictionary Fixed (line 16) maps each broken source material to a repaired new Material(m) copy (lines 54-55). Nothing removes entries: grep finds no Clear or Remove on Fixed. Callers such as MagazineProp.cs:684, WeaponDrops.cs:1033 and GrenadeDud.cs:132 can pass new source material instances on each spawn or drop.
  why:    Each repaired copy holds references to its textures, so the textures of dropped magazines and weapons that the game has destroyed stay resident for the rest of the session. Long sessions with many drops would grow memory. The magnitude is unverified because it depends on whether those source materials are per-instance.
  change: Prune the cache on insert: remove every entry whose key or value is destroyed (kv.Key == null || kv.Value == null), and Destroy the repaired copy when its source dies. Alternatively key the cache by (shader name, material name) instead of the material instance.
