[major/medium] src/Weapons/MagazineProp.cs:839  Procedural magazine box rotated to insert axis but sized in magazine-box axes
  what:   Quaternion orient = Quaternion.LookRotation(frontLocal, insertLocal); (839) tmp.transform.localRotation = orient; (840) localScale = size (842, size = magBounds.size from line 830) ; Vector3 worldishSize = orient * new Vector3(size.x, size.y, size.z); return new Bounds(tmp.transform.localPosition, Abs(worldishSize)); (844-845). magBounds is measured in the magazine's own idle frame (PoseSampler.LocalBounds via WeaponAnalyzer.cs:2071), the same frame as prop space. The cube's local Y is turned to insertLocal, but its scale is applied as if the box axes were already (cross, insert, front).
  why:    When the procedural fallback is used (rig.Magazine null, or CheckedCopy rejects the copy: a skinned mesh that ExtractBoneTriangles cannot read, or parked parts), the insertion axis comes from MagAxisFromShape (WeaponAnalyzer.cs:2228-2231 and 2262-2292), which picks the box's longest axis. For a magazine whose longest box side is its local X, insertLocal = -X, so the cube's Y (insert) gets size.y, the short side. A 12 cm magazine is then drawn and collided as about 2.5 cm along its insertion axis. TipLocal/BaseLocal (lines 150-151), the grip in HoldPose (920-930), the colliders (lines 199, 202) and the pouch display (BuildDisplay line 420 uses the same BuildProcedural) all come from that wrong box. The returned Abs(orient*size) also misstates the extents for non-permuted orientations (tilted principal axis or curved magazines).
  change: For PropKind.Magazine keep the cube in the magazine's own frame: tmp.transform.localRotation = kind == PropKind.Magazine ? Quaternion.identity : orient; and for magazines return new Bounds(tmp.transform.localPosition, size) with no orient. magBounds is already in prop space, so the box needs no re-orientation. insertLocal and frontLocal then only feed HoldPose and the tip/base, which are computed from the correct box. Keep orient for the rocket capsule.
