[minor/low] src/Rig/HandModel.cs:382  Weapon-arm mode disables the glove solid that keep-out and support wrap rely on
  what:   SetVisible(false) sets `_skinValid = false` (line 386), and UpdateSkin returns early when not visible (line 750). NearSkin is used by the support-hand wrap (HeldWeapon.cs:1720) and the magazine keep-out (ReloadInteractions.cs:1845).
  why:    In this mode the drawn hand is the weapon's arm, but the collision logic that keeps a magazine and the support hand out of the gun hand cannot see it. The comment at line 386 suggests this is deliberate ('a hidden glove is no solid'), so confidence is low.
  change: If it is not intended, base `_skinValid` on whether the palm was placed this frame, not on `_visible`, so that the glove's skin keeps existing when Suppressed. Keep the gate for HiddenByHeld.

[minor/medium] src/Weapons/ModHand.cs:43  Proximity fallback overwrites finger roles already matched by name
  what:   Lines 34-41 assign `_index` and `_pinky` from names. Lines 43-64 then run `if (_index == null || _pinky == null) { ... _index = near; _pinky = far != near ? far : null; }`, which reassigns both roles even when one of them was matched by name.
  why:    On a rig where only one finger is named (for example 'Index' plus 'Finger_4'), the named index is replaced by the finger nearest the thumb bone, and the pinky is replaced by the farthest finger whatever its name. `across` (line 143, `_index.position - _pinky.position`) then spans the wrong fingers, so the palm roll of the snap pose (line 157) is off, and a pistol grip can turn the glove palm the wrong way.
  change: Fill only the missing role, from the unassigned fingers: `if (_index == null)` take the finger nearest the thumb that is not `_pinky`; `if (_pinky == null)` take the farthest finger that is not `_index`. Leave name matches untouched.
