[major/medium] src/Input/VRInput.cs:341  Outage timeout drops release edges and re-presses still-held buttons (d5a1423)
  what:   The timeout branch `else if (Time.unscaledTime - _noDataSince > 0.5f) { Array.Clear(Held, 0, Held.Length); ... }` (VRInput.cs:341-344) clears Held without setting Released. Before d5a1423, ClearEdges only cleared Pressed and Released, so a hold survived the outage and a release that happened during it arrived as one Released edge on recovery. On the next good frame the edge code reads `bool was = Held[a, slot];` (224), then sets `Pressed[a, slot] = state && !was;` (226) and `Released[a, slot] = !state && was;` (227).
  why:    A grip or trigger released during an outage longer than 0.5 s never produces Released. WeaponSystem.cs:674 (`if (dom.GrabReleased)`) therefore never starts the grip-to-hold let-go, so the gun stays in the hand; ThrowAndMelee.cs:84 misses the trigger release that throws a grenade. A button still physically down when data returns gets a fresh press: Pause opens the menu (GameInputBridge.cs:107), FireMode flips semi/auto through FireSelector.Toggle (GameInputBridge.cs:245 to WeaponSystem.cs:486), Sprint toggles (GameInputBridge.cs:309-311), and GrabPressed fires again (VRHand.cs:259).
  change: In the timeout branch, for every action and slot that is Held, set Released to true, set Held to false and set a Ghost flag for that slot. In the edge loop, while Ghost is set, keep Held, Pressed and Released false (the button reads as up) and clear Ghost only once state is false. Keep clearing Move, TurnStick, Trigger and Grip so the sticks still stop after 0.5 s. Alternative: go back to freezing Held through the outage and keep only the stick and analog clearing, accepting that a held button stays down during the outage.
