[major/medium] src/UI/CanvasManager.cs:127  Flatten and re-place keyed only to opening; a menu that becomes Menu while visible is never flattened
  what:   Line 118: `bool opening = visible && !t.Visible;` Lines 119-126 recompute `t.Role` on `opening || visible && (Time.unscaledTime >= t.NextRoleCheck || gameplayChanged)`. Lines 127-131: `if (opening && t.Role == CanvasRole.Menu) { t.Placed = false; CollectFlat(t); }`. CollectFlat (lines 228-249) is the only writer of t.Flat, and KeepFlat (line 280) only acts on t.Flat.
  why:    A canvas that is already visible but classified Hud (its buttons not yet active or interactable on the first visible frame, or GameMenuOpen flips while it is already showing) becomes Menu on the 0.5 s recheck or the gameplayChanged path. Because opening is false, CollectFlat never runs, t.Flat stays empty, and deep children (the options Game page case from 077d751, 150 units deep) are never flattened, so that panel draws behind its background. The 3a342d1 rewrite narrowed this window but did not close it; the gate on opening was already there before the change.
  change: Capture `CanvasRole before = t.Role;` before the recheck block (before line 119). Replace line 127 with `if (t.Role == CanvasRole.Menu && (opening || before != CanvasRole.Menu)) { t.Placed = false; CollectFlat(t); }`. The Placed reset is harmless on a Hud-to-Menu flip.
