[minor/medium] src/Rig/VRRig.cs:582  Roomscale step calls CharacterController.Move on every frame the head moves over 0.3 mm
  what:   RoomscaleFollow gates the move with `if (sq > 1e-7f && sq < 0.1225f && player.controller != null && player.IsMovementEnabled())` (VRRig.cs:572) and then calls `player.controller.Move(d);` (582). Lines 565-570 return early while sq <= 1e-7f, so sub-0.3 mm motion accumulates in _lastHeadLocal. FirstPersonController.Move (.ref/decompiled/firstpass/UnityStandardAssets.Characters.FirstPerson/FirstPersonController.cs:215) is a CharacterController.Move sweep.
  why:    Runs once per render frame (up to 90 per second) whenever head motion exceeds 0.3 mm, on top of the game's own CharacterController.Move (FirstPersonController.cs:452). A sweep typically costs tens of microseconds (not measured), so up to about 0.1 ms of the 11 ms budget. Each Move also runs the GunCollider Harmony hooks on CharacterController.Move (reports/agents/perf-verified.txt #5, not re-read here).
  change: Raise the 1e-7f in lines 565 and 572 to 2e-6f (about 1.4 mm). Motion below the gate keeps accumulating in _lastHeadLocal, as the early return already does, so nothing is lost; the body trails the head by at most about 1.4 mm. Capture a -rfvr-perf run before and after, and drop the change if the Move cost is small.

[tiny/low] src/Rig/GroundCheck.cs:55  Ground cast fills a fixed 64-entry buffer and never checks for overflow
  what:   `int n = Physics.SphereCastNonAlloc(ray, radius, Hits, maxDistance, mask);` (55), with `Hits = new RaycastHit[64]` (22) and a loop to n (59) that never checks n against Hits.Length.
  why:    Runs once per FixedUpdate, not per frame. The all-hits query is probably dearer than the closest-hit SphereCast it replaces, so tens of microseconds per physics step (not measured). When a dense pile returns more than 64 hits, the nearest ground can be cut off and Cast returns false for that step, so moving-platform carry is lost for that step.
  change: If n == Hits.Length, grow a static buffer once (for example to 256) and repeat the cast before picking the nearest hit.

[tiny/low] src/Rig/IntroStage.cs:278  Intro title scan runs scene-wide Find calls about 7 times at startup
  what:   Update gates the scan on `_isIntro && _phase != Phase.Done && Time.unscaledTime >= _nextTitleScan` (IntroStage.cs:75) with `_nextTitleScan = Time.unscaledTime + 0.1f` (78). PlaceTitleInWorld then calls FindObjectsOfType<Canvas>() (278), FindObjectsOfType<TextMesh>() (317), and GameCamera(), which calls Camera.allCameras (330, allocates an array).
  why:    Phase reaches Done after about 0.65 s (Measuring 0.25 s, Verifying 0.4 s), so this is about seven scans with allocations in the first second of the intro, not a per-frame cost. Magnitude not measured. The comment at line 76 says the scan also catches text that switches on later in the intro; the Done gate stops that after about 0.65 s, so such text stays screen-space.
  change: If later text must be placed, keep a cached list of canvases and check for new ones about every 0.5 s instead of FindObjectsOfType at 10 Hz. Otherwise correct the comment at IntroStage.cs:76 to match the gate.

[tiny/medium] src/Rig/VRRig.cs:407  Menu after Quit to menu throws every frame through the GameMainCamera fallback
  what:   FollowTarget guards the spectator and LocalPlayer lookups with Unity's null test (VRRig.cs:388-396), then falls back to `cam = GameContext.GameMainCamera;` (407). That calls GameManager.GetMainManagedCamera, which does `LocalPlayer.controller?.GetActiveCamera()` (.ref/decompiled/Assembly-CSharp/GameManager.cs:392). GetActiveCamera reads `tpCamera.enabled` (.ref/decompiled/Assembly-CSharp/FpsActorController.cs:1095). The game never clears LocalPlayer.controller (its only assignment is LocalPlayer.cs:13), so once the player is destroyed the `?.` passes and the read throws MissingReferenceException, which GameContext.cs:163 swallows.
  why:    One managed throw and catch per frame in the main menu after Quit to menu, the case the comment at VRRig.cs:386-387 says was fixed. The catch is silent, so no log shows it. Tens of microseconds per frame, menu only, nothing during play.
  change: Before line 407, skip the game getter when the stored controller is destroyed: `cam = !ReferenceEquals(LocalPlayer.controller, null) && LocalPlayer.controller == null ? Camera.main : GameContext.GameMainCamera;`.

[tiny/high] src/Rig/VRRig.cs:742  Head pose fetched and written to every head camera twice per frame
  what:   UpdateHeadPose() runs in Update (VRRig.cs:281) and again at the top of BeforeRender (742). Each run calls OpenVR.Compositor.GetLastPoseForTrackedDeviceIndex and writes localPosition and localRotation on every head camera (166-184).
  why:    Two native pose reads and transform writes per frame, a few microseconds. The Update call feeds same-frame game logic, so only the BeforeRender call is redundant.
  change: In BeforeRender, skip UpdateHeadPose when it already ran this frame (store Time.frameCount in UpdateHeadPose and compare). Keep the _neutralPending handling in BeforeRender (743-747) intact.

[tiny/high] src/Rig/VRRig.cs:989  UpdatePostProcessing looks up the PostProcessLayer every frame
  what:   `PostProcessLayer source = reference.GetComponent<PostProcessLayer>();` runs in every BeforeRender (VRRig.cs:989), followed by five property writes to _postProcess (1011-1017).
  why:    A GetComponent is well under a microsecond and the writes are cheap. The path only runs when PostProcessing is on, which is off by default (VRConfig.cs:160).
  change: Cache `source` with the same throttle used for layerCullDistances (VRRig.cs:971-974): look it up when the reference camera changes or every 45 frames.
