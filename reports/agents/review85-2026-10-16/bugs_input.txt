[minor/medium] src/Input/GameInputBridge.cs:375  Down-stick latch survives death: respawn flips prone
  what:   Compute() returns early while dead (GameInputBridge.cs:130-134), so UpdateStickJumpCrouch never runs. _downLatch, _downSince and _proneTriggeredThisHold keep their values. ResetToggles() (lines 451-456) clears only SprintActive, CrouchToggled and ProneToggled. It is called on respawn (VRRig.cs:308-310), but the latch survives it. On the first alive frames, `if (!_proneTriggeredThisHold && Time.unscaledTime - _downSince > 0.6f) { ProneToggled = !ProneToggled; ...}` (375-381) fires again with no new push, because the latch branch runs regardless of the current stick position.
  why:    Die while the turn stick is pushed back past -0.8 (the usual way to die while retreating) and the player respawns prone, whether or not the stick is still held. Needs TurnStickJumpCrouch, which defaults to true (VRConfig.cs:187-188).
  change: In ResetToggles() (GameInputBridge.cs:451-456), also set `_downLatch = false; _jumpLatch = false; _proneTriggeredThisHold = false; _sprintClearsStance = false;`. Keep the call at VRRig.cs:310. A stick still held at respawn then starts a fresh flick instead of resuming the old one.

[minor/medium] src/Input/TurretAim.cs:22  Turret hand-aim follows the settings hand, not the gun hand
  what:   `if (VRConfig.TurretAim.Value == TurretAimMode.Hand && rig.SetDominant.Tracked) return rig.SetDominant.Pointer.Forward;` (lines 22-24). SetDominant is Hands[VRInput.Dominant], the handedness setting (VRRig.cs:63-64). The config text says turrets follow "your weapon hand's pointing direction" (VRConfig.cs:208-209). Dominant is the gun hand (VRRig.cs:57-58). After a hand pass the two differ: WeaponSystem.cs:728 and 746 call VRInput.SetGunHand. The turret's trigger reads GunHand (GameInputBridge.cs:102 and 121, which runs in seats too).
  why:    Pass the weapon to the off hand (right-handed setup) and enter a mounted gun in Hand mode: the turret swings with the empty right hand while the left trigger fires.
  change: Use rig.Dominant (the gun hand, VRRig.cs:58) on lines 22 and 24 so the code matches the config text. If the settings hand was intentional, change VRConfig.cs:209 and the comment at VRRig.cs:63 instead.

[minor/low] src/Input/VRInput.cs:610  Trigger held during a weapon hand pass becomes the other action
  what:   SetGunHand (610-614) changes the Fire/Use slot mapping at once (Slot, 625-641). Nothing carries the physical state across, so GetHeld(Fire, GunHand) reads the other hand's trigger slot, and GetHeld(Use, off) reads the Fire slot. The callers have no held-trigger check: WeaponSystem.cs:728 (TakeIntoHand) and 746 (PassToOtherHand). Compute then sees a Down edge (GameInputBridge.cs:121 Fire via MergeButtonDown at 441; line 142 Use).
  why:    A right trigger still held when the weapon passes to the left hand makes the free hand read as Use. The game's UpdateUse reads GetButton(Use) on foot (FpsActorController.cs:1821-1843), so a hovered seat or usable is entered. A left trigger held during the pass fires a Fire edge at the swap.
  change: On a mapping change in SetGunHand, for Fire, Use, SlideRelease, Squad, MagRelease and Map on each hand, copy the held state into a suppressed flag that GetHeld and GetPressed treat as false until that physical input is released. Alternatively, refuse PassToOtherHand and TakeIntoHand (WeaponSystem.cs:713, 735) while GetHeld(Fire) or GetHeld(Use) is true on that hand.

[tiny/low] src/Input/ScriptKeys.cs:186  Tap aimed at a destroyed script reaches every script
  what:   `if (v.Target != null && v.Target != script) return false;` (186). Target is a Unity object. Once the weapon's script is destroyed, `v.Target != null` is false, so the target filter is skipped. The tap from Tap(key, target) (80-90) then reaches every script that polls the key until ReleaseAt (TapSeconds = 0.08).
  why:    A fire-mode tap followed by a weapon switch within 80 ms lets HUD or mutator scripts see the same key press for the rest of the tap.
  change: Add `public bool Targeted;` to VirtualKey. Set `v.Targeted = target != null;` in Tap, and in Query use `if (v.Targeted && v.Target != script) return false;`. A destroyed target then fails the check instead of being treated as untargeted.
