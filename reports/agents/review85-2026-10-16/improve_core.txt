[major/high] src/Core/VRManager.cs:50  Headset idle because SteamVR is off: flat game, only a log line
  what:   ShouldStartVR returns false when vrserver is not running and AutoStartSteamVR is off (VRManager.cs:111-130). The caller then does Log.Info("Not starting VR: " + reason + " Launch with -vr to force it.") and yield break (lines 48-52). The OpenVRRuntime.Start failure path is also Log.Warn only (lines 53-56). Nothing is shown in the game or the headset, and VRManager never retries.
  why:    A player who starts the game through Steam with SteamVR not running gets a flat screen with no explanation, and the headset stays idle. The only clue is a line in the BepInEx console. Starting SteamVR after the game does nothing until the game is restarted. The mod has no notification helper (grep finds none), so the message needs a new small UI element.
  change: On this branch and the OpenVRRuntime.Start failure branch, show a visible in-game notice (flat-screen text) saying SteamVR is not running: start it, then restart the game, or enable AutoStartSteamVR. Use Log.Warn instead of Log.Info. Optionally poll for the vrserver process every few seconds while flat, and start VR when it appears.

[minor/medium] src/Core/GraphicsPresets.cs:95  Switching to Game restores launch-time quality, not the menu's
  what:   _gameQuality is captured once, in ApplyProfile (lines 157-167: if (_gameQuality == null) { _gameQuality = new Profile { ... } }). The Game branch (lines 95-98) calls RestoreGameQuality() (lines 135-153), which writes that launch-time snapshot back, then sets _gameQuality = null. [minor/medium] src/Core/VRManager.cs:273  Putting the headset back on resumes the match at once
  what:   OnHeadsetWorn(true) calls GameManager.UnpauseGame() in the same call as the worn event: if (_pausedForHeadset && !_pausedForDashboard && GameManager.instance != null && GameManager.IsPaused() && !menuOpen) { GameManager.UnpauseGame(); } (lines 272-277).
  why:    The match restarts the instant the headset is seated, while the player is still settling the lenses, strap or view. Enemies can fire in that moment and the player gets no beat to re-orient. The pause itself is well guarded, so only the resume is abrupt.
  change: On worn=true, store _resumeAt = Time.unscaledTime + 3f instead of unpausing, and call UnpauseGame from Update once that time has passed. Cancel the countdown if the headset comes off again or a menu opens. Leave the dashboard path as it is.
