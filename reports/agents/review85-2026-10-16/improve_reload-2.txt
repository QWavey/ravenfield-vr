[major/high] src/Weapons/ReloadInteractions.cs:1647  A slide or bolt that closes on its own is silent and unfelt
  what:   BeforeRender's spring branch (1644-1653) is `_held.SlideOffset = Mathf.MoveTowards(_held.SlideOffset, 0f, 6f * dt); if (_held.SlideOffset <= 0f) { _returning = false; _held.Nudge(Rig.AimWorld * 0.22f, 25f); }` with no Sounds.Play and no Haptic. The only closing sound on release is EndRack's chamber path (1597-1601: SlideForward plus two haptics), which runs only when `_rackedBack` (pulled past 80%). A hand-driven bolt closed without a feed plays nothing: the feed sound at 1557 needs `_rackedBack`, and when released below 10% travel the rest is snapped in one frame at 1654-1657 (`else if (!_racking) _held.SlideOffset = 0f;`).
  why:    A player who pulls a slide back half way and lets go gets the slide slamming home with only a nudge, while pulling it past 80% gives a clack and haptics at release. The same action feels different depending on how far it was pulled. A bolt pushed nearly home without a feed loses its last tenth of travel silently and at once.
  change: Make the closing feedback one event in the `_returning` completion (1648-1652): call `_held.Sounds.Play(MechSound.SlideForward, RackPointWorld)` and `_sys.Rig.Dominant.Haptic(0.04f, 120f, 0.5f)`. For hand-driven bolts with no feed, add the same sound and haptic in EndRack's HandDriven branch (1577-1584) when the release leaves the bolt closed, guarded by a bool set where the feed sound at 1557 plays so a fed bolt is not clacked twice.

[minor/high] src/Weapons/ReloadInteractions.cs:1647  Spring return speed is a fixed 6 m/s, so short slides pop shut
  what:   `_held.SlideOffset = Mathf.MoveTowards(_held.SlideOffset, 0f, 6f * dt);` (1647). The speed does not use `Travel` (defined at line 73 from Data.SlideTravel).
  why:    Return time is Travel / 6 s: a 5 cm slide closes in about 8 ms, under one frame at 90 Hz (11 ms), while a 15 cm bolt takes 25 ms. Short slides snap shut in one frame, although the comment says spring slides slam home in a few hundredths of a second for every weapon, and the sound (once added per finding 1) would start with no visible motion.
  change: Use `Mathf.MoveTowards(_held.SlideOffset, 0f, Travel / 0.03f * dt)` so every spring-driven close takes about 30 ms whatever the weapon. Long bolts get marginally slower and short slides become visible. Confirm in game.
