[minor/medium] src/Weapons/ReloadInteractions.cs:1095  Rocket lined up in front of the tube jumps up to 12 cm inward
  what:   Loose line-up (commit d077bdd, lines 1077-1080): `lined = true; prop.RailHandOffset = along - looseDepth; prop.RailLateral0 = lateral; along = looseDepth;`, with LooselyLined returning `depth = Mathf.Max(0f, along)` (tail depth). When the tail is in front of the mouth (along < 0, accepted down to -0.12), looseDepth is 0, so the lining sets `prop.RailDepth = Mathf.Clamp(along, 0f, prop.RailLength)` (line 1095) = 0 while RailHandOffset keeps the negative unclamped value. Each later frame runs `along -= prop.RailHandOffset` (1120) and clamps again (1130).
  why:    A rocket held in front of the muzzle, the normal RPG loading case, is drawn at the mouth instead of where the hand holds its tail. The OnRail setter eases the prop over 0.08 s (MagazineProp.cs ~103, ShowAt ~116), so the rocket visibly snaps up to 12 cm into the tube. Then RailDepth stays |tail0| deeper than the hand for the whole push (ShowOnRail's HeldPalm moves the glove to match, so the glove sits off the real hand). The release test `along < -0.03f` (1121) fires on the shifted value, so the release point is also off by the same amount. The rocket still loads.
  change: Let a loosely lined rocket's rail depth go negative instead of clamping it to 0. In the loose branch set `prop.RailHandOffset = 0f` and `along` unclamped (RailDepth in [-0.12, RailLength]). Add a per-prop rail floor on MagazineProp (default 0, set to -0.12 in the loose branch). Use that floor instead of the literal 0 in the clamps at 1095 and 1130, and as the release bound at 1121 instead of -0.03f (otherwise a rocket lined at -0.05 is dropped on the next frame). Remove the offset line 1078. Note that the stale comment at 1074-1076 still says 'either end first', but LooselyLined is tail-first only since b0a99c2.
