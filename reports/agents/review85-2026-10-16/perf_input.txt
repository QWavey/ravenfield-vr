[minor/low] src/Input/ScriptKeys.cs:390  KeyCode-keyed Dictionary lookup on every script key poll may allocate
  what:   public static string Name(KeyCode code) { if (!NameCache.TryGetValue(code, out string name)) ... } (lines 390-397), with NameCache declared as Dictionary<KeyCode, string> (line 382). Called from every InputProxy.GetKey / GetKeyDown / GetKeyUp(KeyCode) postfix (lines 452-459) before Merge's Enabled check, so on every poll by every script, every frame.
  why:    On the Mono runtime that Unity 2020.3 ships, I believe EqualityComparer<KeyCode>.Default boxes the enum for GetHashCode and Equals, so each lookup may allocate 24-48 bytes. The number of polls per frame depends on how many scripts poll keys (likely tens). The effect is GC churn, not frame time. Not measured here: confirm with the Profiler's GC Alloc column while a weapon with a fire-mode or magnifier script is held.
  change: Replace NameCache with an array indexed by the enum value: `private static readonly string[] NameByCode = new string[512];` and in Name: `int i = (int)code; if ((uint)i < (uint)NameByCode.Length) return NameByCode[i] ?? (NameByCode[i] = BuildName(code)); return BuildName(code);`. Keep the dictionary-free path for values outside the array.
