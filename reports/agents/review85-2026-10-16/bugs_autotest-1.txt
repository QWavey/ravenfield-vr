[major/high] src/Core/AutoTest.cs:249  A thrown exception ends Run(): no Write and no Quit, the game stays open at the match
  what:   Run() (249-336) calls its phases with bare yield returns: 'yield return TestWeapons();' (291, 330) and 'yield return FlashFilm();' (305). There is no try anywhere in Run. Write() and Application.Quit() run only at 334-335 (and 311-312, 318-319 etc.). The only per-weapon containment is the equip try/catch (2673-2680, 2693-2700) plus the fire try in Shoot (746-757) and FlashCheck (964-973). Other per-weapon calls are unguarded, e.g. 'body.position' (1226), 'auto.Fire(...)' (804), 'active.ammo' (962), 'w.Fire(...)' (1029). The report is otherwise written only by the Application.quitting handler (106-113).
  why:    Any NullReference or MissingReference in a per-weapon check propagates out of TestWeapons and Run. Unity logs it and the coroutine chain stops. Nothing calls Write() or Quit(), so the game sits at the match with no RavenfieldVR-autotest.txt, which looks like a hang. The per-weapon 'lines' list reaches Results only through ReportWeapon (called at 2769, 2780, 2857, 3092), so a weapon that throws loses its whole entry, not just the failing check. This is a candidate explanation for a missing or empty M4A1 entry.
  change: Add a guard that does not yield inside a try/catch (C# forbids that, CS1626): static IEnumerator Guarded(IEnumerator inner, string what) { while (true) { object cur; try { if (!inner.MoveNext()) yield break; cur = inner.Current; } catch (Exception e) { Problem($'[{_context}] {what}: {e.GetType().Name}: {e.Message}'); yield break; } yield return cur; } }. In Run wrap each phase: yield return Guarded(TestWeapons(), 'weapons'); FlashFilm likewise. In TestWeapons wrap each per-weapon check call the same way (PassHandCheck, SteadyCheck, FlashCheck, LensBurstCheck, ReloadFilm, the Reload.* self-checks). Move the ReportWeapon call for a weapon into a finally so its lines are still written when a check throws.

[major/medium] src/Core/AutoTest.cs:816  FlashFilm's finally never stops the eye film, so a thrown exception leaves it recording every frame
  what:   FlashFilm starts the film at 710 (EyeFilm.Begin on the UI camera). The try at 766-815 has a finally at 816-819 that only does 'Rig.VRHand.Scripted[side] = null;'. [minor/low] src/Core/AutoTest.cs:237  The match wait gives up after 300 frames, so a slow load can silently skip the whole test
  what:   WaitForMatch: 'for (int i = 0; i < 300 && !_started; i++)' (237) counts frames, not seconds, and then ends. Each scene load starts a new one (97) and nothing retries it. Run's own deadlines (252, 'Time.realtimeSinceStartup + 120f') are in real time, so the two are inconsistent.
  why:    On a slow load or a low frame rate (the WristViewCheck comment at 1506 mentions the null driver at 12 frames a second), the match can become in-game after the 300th frame. Then Run never starts, nothing is written, and the game sits at the menu. Whether IsIngame is false during loading is not visible in this area, hence the low confidence.
  change: Use a real-time deadline as Run does: 'float until = Time.realtimeSinceStartup + 180f; while (!_started && Time.realtimeSinceStartup < until) { if (GameManager.IsIngame(out bool noGameplay) && !noGameplay && ActorManager.instance != null) { _started = true; yield return Run(); yield break; } yield return null; }'.

  what:   Finish waits only 3 s for _pending (79-82), then waits on Queued only (85-88), sets _stop (89) and joins the writer. WriterLoop returns when the queue is empty and _stop is set (176-180). AsyncGPUReadback callbacks that complete later enqueue (153-156), but nothing drains them afterwards.
