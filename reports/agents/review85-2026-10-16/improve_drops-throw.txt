[major/high] src/Weapons/ThrowAndMelee.cs:319  Grenade pin gives no hover cue when the off hand reaches it
  what:   UpdatePin acts only on the grab: `if (!_holdingPin && off.Tracked && off.Role == HandRole.Free && off.GrabPressed && Vector3.Distance(off.Palm.position, pin) < PinGrabRadius)`. Nothing buzzes when the palm enters the 0.07 m radius (PinGrabRadius, line 22). WeaponDrops.cs:583-586 does buzz on entering reach ('you can grab this').
  why:    The pin is a 1.6 mm wire ring on a grenade, and the only sign it can be grabbed is an invisible 7 cm sphere. The hand passes it with no response, and the player keeps closing the fist until it happens to catch the pin.
  change: Add `private bool _pinHover;`. In UpdatePin compute `bool near = !_holdingPin && off.Tracked && off.Role == HandRole.Free && Vector3.Distance(off.Palm.position, pin) < PinGrabRadius;` then `if (near && !_pinHover) off.Haptic(0.01f, 160f, 0.2f); _pinHover = near;`. Reset `_pinHover = false` in ResetVisuals and PullPin. Same pattern as WeaponDrops.cs:583-587.

[major/medium] src/Weapons/ThrowAndMelee.cs:605  A fast swing that connects with nothing is silent
  what:   BeforeRender detects the swing (`speed > VRConfig.MeleeSwingSpeed.Value`, line 605) and calls Swing only. Nothing plays a whoosh: MeleeHandler has no Sounds.Play, the only swing output is PlaySwingAnimation on a hit (line 679), and MechSound (ProceduralSounds.cs:7) has no whoosh entry.
  why:    Air swings make no sound and no haptic. The player cannot tell a registered swing from a miss, and the blade has no weight in sound.
  change: Track `_swinging`: on the frame speed rises above the threshold while !_swinging, call `_sys.Sounds.Play(MechSound.Whoosh, tip, Mathf.Clamp01(speed / 6f))` and set _swinging = true; clear it when speed < 0.5 x threshold. Add Whoosh to the MechSound enum (ProceduralSounds.cs:7) and synthesize it in the constructor from the existing Burst/Scrape helpers: about 0.2 s of band-passed noise with a falling pitch.

[major/high] src/Weapons/ThrowAndMelee.cs:716  A blade hitting a static wall gives no haptic, animation or sound
  what:   Cast returns `body != null || destructible != null` for a wall hit (line 716). A static wall has neither, so Cast returns false; Swing (lines 676-680) then skips the haptic and PlaySwingAnimation, and _lastHit is not set, so Cast re-runs every frame of the swing. The game's own ShootMeleeRay (MeleeWeapon.cs:197-208) also plays nothing for a static wall.
  why:    In VR a sword or axe swung into a concrete wall passes through with no response. A solid stop is the main thing that makes a melee hit feel real.
  change: Return a hit kind from Cast (Flesh, Body, Destructible, Vehicle, Wall) instead of bool. For Wall: `_sys.Rig.Dominant.Haptic(0.06f, 110f, 0.8f)`, play a clang, and set `_lastHit = Time.time` so one swing gives one jolt. The clang needs a sound (see the whoosh finding) or can reuse MechSound.Casing at higher volume.

[major/high] src/Weapons/WeaponDrops.cs:159  Dropped weapons and duds hit the ground silently
  what:   Spawn adds a plain Rigidbody (`var body = root.AddComponent<Rigidbody>();`, line 159; same in DropHeld at line 939 and GrenadeDud.cs:72) with no collision handler. The only collision sound in the weapon code is Casings.cs:488-499 (OnCollisionEnter, speed >= 0.6, rate-limited). Pin rings (PinRing.Drop, GrenadeDud.cs:385-399) are silent too.
  why:    A rifle sliding off a tailgate, or a dud bouncing off a wall, makes no sound. In VR, audio is the main cue that an object has hit something, and the mod already does this for casings.
  change: Add a small MonoBehaviour with the Casings.cs:488 pattern: OnCollisionEnter skips when c.relativeVelocity.magnitude < 0.8 or within 0.25 s of the last sound, otherwise `WeaponSystem.Instance.Sounds.Play(MechSound.MagKnock, transform.position, Mathf.Clamp01(speed / 4f) * 0.5f)`. Attach it to the root in Spawn (after line 149), DropHeld (after line 894) and GrenadeDud.Spawn (after line 46). A dedicated clip can be added to ProceduralSounds.cs later.

[major/high] src/Weapons/WeaponDrops.cs:777  The player's displaced weapon becomes an ordinary drop and can be culled

[minor/medium] src/Weapons/ThrowAndMelee.cs:75  Arming buzzes every frame of the hold instead of once
  what:   `if (VRInput.GetPressed(DigitalAction.Fire, hand.Side) && !GameContextBlocksThrow()) { _armed = true; hand.Haptic(0.02f, 100f, 0.3f); }` runs every frame the trigger is down. VRInput.Haptic raises Touch pulses to at least 45 ms and 0.35 amplitude (VRInput.cs:538-539), so the hand hums for the whole hold.
  why:    There is no moment that says 'armed': the rumble is the same from first frame to last, so arming, holding and the release pulse (line 176) blur together, and the constant hum tires the hand.
  change: Buzz on the edge only: `bool pressed = VRInput.GetPressed(...) && !GameContextBlocksThrow(); if (pressed) { if (!_armed) hand.Haptic(0.04f, 120f, 0.5f); _armed = true; }`. Do not write `_armed = pressed` every frame: that clears _armed before the release check at line 84. Keep the blocked-menu reset at lines 80-83.

[minor/medium] src/Weapons/ThrowAndMelee.cs:84  A soft trigger release does nothing and says nothing
  what:   `if (_armed && VRInput.GetReleased(...)) { _armed = false; ... if (v.magnitude > 1.1f && Throw(weapon, hand, v)) {...} }`. A release at or under 1.1 m/s clears the arm and does nothing else: no haptic, no sound, and the pin stays out. The grip path uses a different limit (1.6 m/s on the body velocity, line 106).
  why:    The player throws, nothing happens, and nothing says why, so they swing harder and try again. The two throw paths also disagree on how hard a throw must be.
  change: Add an else branch for the sub-threshold release: `else hand.Haptic(0.02f, 60f, 0.15f);`. Move the 1.1 m/s and 1.6 m/s limits into VRConfig next to ThrowVelocityMultiplier (VRConfig.cs:271) so they can be tuned together.

[minor/medium] src/Weapons/WeaponDrops.cs:160  Every dropped weapon has the same 3 kg mass
  what:   `body.mass = 3f;` at line 160 (Spawn) and line 940 (DropHeld); duds use `body.mass = 0.45f;` (GrenadeDud.cs:73). Weapon type is not used. The decompiled game has no weight data (grep finds no weight field), so the mod must decide.
