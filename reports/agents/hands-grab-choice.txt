#1 [major] [confidence medium] Foregrip grab is accepted along the whole handguard but released in the same frame when the palm is more than 35 cm from the support point
   where: src/Weapons/ReloadInteractions.cs:175 (release, Update switch, case HandRole.Foregrip); acceptance at :281-285 (TryGrab choice 4) and :344-358 (ForegripDistance)
   trigger: a grip squeeze with the off palm on the front part of a long rifle's handguard, more than 0.35 m from GripRig.SupportPoint (the default support point is grip + 0.22 m along the aim axis, WeaponAnalyzer.cs:234 and :724, so this is roughly anything beyond 0.57 m from the grip).
   effect: TryGrab sets off.Role = Foregrip, calls SetTwoHanded(true), plays a haptic and consumes the Grab press. Then the switch in the same Update runs case Foregrip: distance > 0.35 gives Role = Free and SetTwoHanded(false). Nothing is held and the grab fails silently. The handguard tip cannot be gripped.
   evidence: Update() line ~161 calls TryGrab when GrabPressed or GrabReaching and Role is Free. TryGrab consider(4) uses ForegripDistance = min(distance to the handguard segment from grip+0.08 to the muzzle, distance to SupportPoint), with r = GrabRadius*1.4 (GrabRadius default 0.09, VRConfig.cs:286). The comment at :345 says "Anywhere along the handguard, from just ahead of the grip to the muzzle". The release at :175 uses only distance to SupportPoint > 0.35. Tasks2.md:76 (task 206) documents the 0.35 m release as deliberate for pulling the hand off a grip, so the release itself is intended. The acceptance and the release just measure different things.
   fix idea: keep the pull-away release but measure it from where the hand took the handguard (store the grab point the way _pressPalm is stored), or reject choice 4 in TryGrab when the distance to SupportPoint is over 0.35 so acceptance and retention agree.

#2 [minor] [confidence medium] The slide-release button path has no !_racking guard, so ReleaseSlide during a rack leaves _returning set while the hand still holds the slide
   where: src/Weapons/ReloadInteractions.cs:136-142 (SlideRelease branch, no !_racking) versus :149 (trigger branch, which does have !_racking); ReleaseSlide at about :1508-1514 (sets _returning = true); BeforeRender branch `else if (_returning)` at about :1544
   trigger: the off hand grips a locked slide or bolt (BeginRack with SlideLocked sets _rackBase = 1), then the dominant hand presses the slide-release button while the rack is still in progress.
   effect: ReleaseSlide chambers and sets _returning = true. BeforeRender then runs MoveTowards(SlideOffset, 0, 6*dt) each frame. UpdateRack resets SlideOffset to the hand's fraction in Update, so the slide renders pulled toward closed while the glove still holds it. When SlideOffset finally reaches 0 the jolt Nudge(AimWorld*0.22, 25) fires once, mid-hold. The render order (Update before BeforeRender) is inferred from the code, not run.
   evidence: Update() :136-142 versus :147-149 (the trigger branch explicitly checks !_racking). ReleaseSlide() sets _returning = true unconditionally. BeforeRender() checks `SlideLocked && !_racking` and `BoltOpen && !_racking` first, so the `_returning` branch is reached while _racking is true.
   fix idea: add !_racking to the SlideRelease branch, or have ReleaseSlide set _returning = !_racking (the rack's own EndRack already sets _returning when the hand lets go).

#3 [minor] [confidence low] IsPump compares the active rig's RackPoint with the grip rig's SupportPoint, which are in different gun spaces when a sub weapon is active
   where: src/Weapons/ReloadInteractions.cs:1379-1380 (IsPump); its use in TryGrab at about :284 (pump redirect from choice 4 to choice 2)
   trigger: the active sub weapon (own WeaponRig, Data = ActiveRig.Data) has CyclesByHand, and the parent gun (GripData) has a support point.
   effect: Distance(Data.RackPoint, GripData.SupportPoint) < 0.15 mixes two origins, so IsPump can be true or false by accident. If false, a pump racked on the handguard is taken as the foregrip, which is the "the pump does not move at all" failure the comment at :282-283 describes. If true, a non-pump gets the pump grasp.
   evidence: IsPump is also used by BeginRack (about :1346) and UpdateGraspAnchor (about :1568). The anchor math itself round-trips through Rig.ToGun/ToWorld and is consistent. Only the IsPump distance test mixes spaces. I did not confirm that any sub weapon in the game has CyclesByHand.
   fix idea: compare in world space, e.g. Rig.ToWorld(Data.RackPoint) against GripRig.ToWorld(GripData.SupportPoint).
