#1 [major] [confidence high] Grabbing a seated magazine re-seats it on the grab frame, so pulling it out by hand never works
   where: src/Weapons/ReloadInteractions.cs:507 (RailHandOffset set), :1047 (along -= RailHandOffset), :1060-1062 (seat test); entry :170, :185, :315-316
   trigger: A detachable magazine is inserted. The off-hand grab is pressed within GrabRadius*1.1 (about 0.099 m) of SeatedMagBaseWorld, and the palm is not more than about 7 cm off the well axis (tip lateral < 0.07).
   effect: PullSeatedMagazine sets RailHandOffset = along_grab - RailLength. On that same frame UpdateHeldProp computes along = along_now - RailHandOffset = RailLength exactly, so RailDepth = RailLength and the 0.96 test at :1060 seats it immediately: Ammo.InsertMagazine, a MagIn sound, a +0.14 gun nudge, and prop.Destroy(). The hand is left empty. The seated magazine only leaves the gun when the grab lands more than about 7 cm off the axis (:1048-1052 drops it off-rail, which is a different symptom). The comment at :504-506 says this offset fixes the bug, but on the grab frame the subtraction cancels exactly, so it does not. SelfCheck (ReloadInteractions.cs around :1813-1818) yields one frame and then reports "magazine: seated" in either case, so the self-test cannot see this.
   evidence: TryGrab :170 -> case 6 :315-316 -> PullSeatedMagazine :495-508 (Attach at :500 sets Role=Magazine; OnRail=true :501; RailDepth=L :502; RailHandOffset :507) -> TryGrab returns to the same Update, and the switch at :172-185 calls UpdateHeldProp(off) :973 in the same frame -> TryMagKick returns false (MagInserted is false, set by AmmoState.EjectMagazine AmmoState.cs:211-222) -> AcceptsNow :994 is true (WeaponKey matches, MagazineProp.cs:230) -> :1047 along = L -> :1054 RailDepth = L -> :1060 SeatProp.
   fix idea: Do not run the seat test for a prop that PullSeatedMagazine started until the hand has drawn it out (for example, a PulledOut flag set when along < RailLength - 0.01 and cleared on seat or drop). Keep the lateral release at :1048 as the only way out on the grab frame, or drop it deliberately. Make the self-check assert the magazine is still held after the frame.

#3 [minor] [confidence medium] Glove keep-out is computed from the glove as last rendered, one frame behind the tracked hand
   where: src/Weapons/ReloadInteractions.cs:1722-1723 (ClearanceAlong call and KeepOut write); src/Rig/HandModel.cs:418-424 (tracked = -_graspOffset - _keepOut, tested against skin from the previous render); HandModel.cs:618 (UpdateSkin at the end of Apply); HandModel.cs:509 (placement uses the current palm)
   trigger: A magazine is on the rail and the off hand moves along the insert axis, for example a fast push into the well or a fast pull out.
   effect: Update runs before the render (VRManager.cs:143-145 Rig.Update, then Weapons.Update, then ReloadInteractions.Update -> UpdateGraspAnchor -> KeepOutOfGun). HandModel.Apply runs later in OnBeforeRender (VRManager.cs around :190-207). So ClearanceAlong tests the skin posed from the previous frame's palm, offset back by the previous frame's offsets. The glove is then placed at the current palm minus `back`. The gap between the tested and placed positions is the palm's per-frame travel. At insertion speeds (about 0.5-1 m/s) that is roughly 5-10 mm, which is more than the 5 mm search step, so the glove can end up a few millimetres inside the receiver or the gun-hand glove. The effect is an estimate from the code; I did not measure it.
   fix idea: Compute the clearance inside HandModel.Apply after the pose is set, against the current skin, or shift the test by (current target - last target) before calling GloveIn.
