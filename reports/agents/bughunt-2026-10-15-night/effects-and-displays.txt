The trigger is not reachable as described, though. VRRig is constructed once per process: VRManager.Start is a one-shot coroutine (src/Core/VRManager.cs:38-89, Rig = new VRRig() at line 62). VRManager lives on a DontDestroyOnLoad host object created once by VRPlugin (src/Core/VRPlugin.cs:51-54). VRRig.Dispose (src/Rig/VRRig.cs:1049, which calls _vignette.Destroy() at line 1052) is reached only through VRManager.Shutdown (VRManager.cs:284-308). Shutdown is called from OnApplicationQuit (line 310), OnDestroy (lines 312-319, only at plugin host teardown), and the startup-failure catch (lines 67-71). In the catch path Rig is still null, so Dispose is not called. A grep over src shows no mid-session VR stop or restart path, and OpenVRRuntime.Stop is called only from Shutdown.

So Destroy runs at most once, at application quit, and the process then exits and the OS reclaims the memory. The leak is roughly one Material, one 128x128 RGBA32 texture (about 64 KB), and a 4-vertex mesh. It does not grow with sessions, so neither a player nor the mod would notice. The suggested fix is reasonable hygiene, but it does not fix a reachable defect. It should also destroy the Mesh.
