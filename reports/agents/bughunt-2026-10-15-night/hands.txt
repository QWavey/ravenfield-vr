Bug hunt (Haiku, read only), area: hands

1. [CONFIRMED] [major] Name regex classes real guns as kits, hiding and freezing the gun-hand glove
   src/Weapons/HeldWeapon.cs:1616
   what: IsKit() falls back to a regex on the weapon's GameObject name (\b(bag|kit|medkit|medic|ammo ?box|first ?aid)\b) for every weapon, whether or not it has a projectile prefab. Any gun whose name contains one of those words is flagged _isKit, and SnapHands (line 1623) sets main.Model.HiddenByHeld = true every frame. HandModel.Apply (HandModel.cs:511-515) then hides the glove and returns before posing it, so the gun-hand glove is invisible and stays frozen at its pickup pose for the whole hold. The regex is meant for kits whose projectile lacks the Ammobox/Medipack/ResupplyCrate component, but it also fires for guns.
   trigger: A rifle, SMG or pistol mod whose weapon GameObject name contains a standalone word such as 'kit', 'bag', 'medic' or 'first aid' (e.g. 'Medic SMG', 'AK kit'). Equip it in VR hands mode: the gun hand shows no glove and the glove does not follow the hand. The frozen skin also stays a live collision solid (see the HandModel.cs:378 finding).
   fix: Apply the name fallback only when the weapon has no projectile prefab: after the component test in IsKit, add `if (projectile != null) return false;` before the regex. Trade-off: a mod kit whose projectile has a projectile prefab but none of the three kit components will no longer be detected.
   skeptic (correct): REAL, high: Verified the full chain in the code. (1) HeldWeapon.cs:1608-1617: IsKit returns true only if the projectile prefab has an Ammobox/Medipack/ResupplyCrate component. Otherwise it falls through to the name regex for every weapon, with or without a projectile. (2) Weapon extends MonoBehaviour (.ref/decompiled Weapon.cs:11). The `name` field at Weapon.cs:259 belongs to the nested SightMode struct, so weapon.name is the GameObject name and a mod gun named 'Medic SMG' or 'AK kit' matches \bmedic\b / \bkit\b. (3) _isKit is assigned once per equip at HeldWeapon.cs:193. It is read only at line 1623 (SnapHands) and by the self-test accessor. (4) SnapHands runs from HeldWeapon.BeforeRender (line 1106), which VRManager.OnBeforeRender calls every frame (VRManager.cs:197-198). It sets main.Model.HiddenByHeld = _isKit (line 1623) on every frame. (5) HandModel.Apply, the per-frame delegate registered at VRManager.cs:177 and invoked at lines 203-208 after the weapon's BeforeRender, calls SetVisible(!Suppressed && !HiddenByHeld) (HandModel.cs:511). It then returns at line 512-515 before any placement. The glove is hidden and not moved while held. HiddenByHeld is only cleared in Release (HeldWeapon.cs:1949, 2039), so it persists for the whole hold. (6) Guns fire via configuration.projectilePrefab (Weapon.cs:1676, SpawnProjectile), so a real rifle, SMG or pistol normally has a non-null projectile and reaches the regex fallback. This confirms the trigger in the finding. I did not verify the secondary claim about the frozen skin remaining a collision solid (HandModel.cs:378 is SetVisible, which only toggles the renderer). That is outside this finding's correctness lens.
      correction: The trigger, mechanism and file/line references are correct. Scope note on the suggested fix: `if (projectile != null) return false;` before the regex fixes firing guns, because they always have a projectilePrefab. Weapons with a null projectilePrefab (for example melee items) still reach the name regex, so an item named e.g. 'Medic Knife' would keep its glove hidden. A fully scoped fix should also skip the regex for ActionType.Melee (or any non-kit action), not only for weapons with a projectile.
   skeptic (reach): REAL, high: Mechanism confirmed in the code. IsKit runs the name regex for every weapon, HandModel.Apply hides the glove and returns before posing it while HiddenByHeld is set, and mod guns named with standalone medic, kit, bag or first aid match. Guns always have a projectile prefab, so the suggested null check does fix the reported gun case.
      correction: The suggested fix is incomplete. Weapons without a projectile prefab, such as melee weapons, still run the name regex after the fix. Restrict the name fallback to thrown kits instead, for example by Action being Throwable or projectile being present.

2. [CONFIRMED] [major] Hidden or suppressed glove never refreshes GraspPointWorld, so arm IK anchors to a stale point
   src/Rig/HandModel.cs:512
   what: Apply() returns at line 512 when Suppressed or HiddenByHeld, before line 533 sets GraspPointWorld. The value stays frozen at the last visible frame. ArmIK.cs:98 uses it as anchorWant = ClampMagnitude(GraspAnchor - GraspPointWorld, 0.05), so the visible off-hand arm is offset by up to 5 cm toward a point the hand left long ago, for as long as an anchor is set (racking, cover, optic).
   trigger: Hands set to 'Weapon's arms' (VRConfig.HandsNow == WeaponArms), with a weapon whose arm rig resolves. HeldWeapon.cs:1110 sets Suppressed on both hands every frame, so GraspPointWorld freezes at the pose from the frame before the weapon was taken. The player then racks the bolt with the off hand (Slide role, GraspAnchor set in ReloadInteractions.cs:1705, onGun false). The support arm sits about 5 cm off the controller throughout the rack.
   fix: Compute target and GraspPointWorld (lines 523 and 533) before the early return, so they stay live while the glove is not drawn. Only the root pose, skin and finger solve need to be skipped while hidden.
   skeptic (correct): REAL, high: The bug exists on the path the finding names. Checked chain:

1. Per-frame order: VRManager.OnBeforeRender (VRManager.cs:197-209) runs Weapons.BeforeRender first, then HandModel.Apply for each hand through the _handApply delegates (VRManager.cs:177, 203-208). Apply is never called directly, so the delegate is the only caller.
2. HeldWeapon.BeforeRender (HeldWeapon.cs:980-993) returns early only when the main hand has no pose. In normal play it reaches lines 1107-1110 every frame: _armIK.Solve(), then SetHandModelsSuppressed(true), which sets Suppressed on every hand in Rig.Hands (HeldWeapon.cs:1919-1928). This happens only when _armIK.Active, i.e. HandsNow == WeaponArms and a chain resolved (HeldWeapon.cs:188-191, ArmIK.cs:38).
3. HandModel.Apply (HandModel.cs:503-515): with Suppressed set, it sets SetVisible(false) and returns at line 512. GraspPointWorld is only assigned at line 533 (HandModel.cs:406 is get; private set; grep finds no other assignment). So it stays frozen at the last value from a frame where Apply ran, the frame before the weapon was taken. Suppressed is cleared only in HeldWeapon.Release (HeldWeapon.cs:2031), so it stays frozen for the whole hold.
4. ArmIK.Solve (ArmIK.cs:95-100) reads GraspPointWorld. With GraspAnchor set, anchorWant = ClampMagnitude(GraspAnchor - GraspPointWorld, 0.05), eased at 30/s into _anchorOffset, which is added to the free arm target at line 100. The arm is visible because HideArms is not called when Active.
5. Trigger: GraspAnchor is set during _racking (ReloadInteractions.cs:1662-1673, assigned at 1707). BeginRack sets Role = Slide (ReloadInteractions.cs:1438). Slide is not onGun unless TwoHanded, so the free target with the anchor offset is used.

The error is real and reaches the visible arm. It saturates at 5 cm once the hand has moved more than 5 cm since the freeze, which is the usual case during a rack. The suggested fix (compute target and GraspPointWorld before the early return) is sound: GraspPointWorld depends only on _hand.Palm, FollowOffset, and the grasp-local point, all live while hidden.

Narrowing and corrections are listed in the correction field.
      correction: Real, with these corrections to the finding:

(b) Precondition: only ArmIK's left (off-hand) branch reads GraspPointWorld (ArmIK.cs:95-100), so the bug needs the off-hand arm chain to resolve (_left.Valid), not just either arm (Active is true if either arm resolves, ArmIK.cs:38).

Suggested fix is correct as stated.
   skeptic (reach): REAL, high: Verified in the code, with one correction to the direction of the offset.

That needs HandsNow == WeaponArms and an arm rig (HeldWeapon.cs:188, ArmIK.Active). 3. [CONFIRMED] [major] Hidden glove keeps its last skin as a live collision solid
   src/Rig/HandModel.cs:378
   what: SetVisible(false) and the early return at lines 512-515 never reach UpdateSkin(), which is the only place _skinValid is set. _skinValid therefore stays true from the last visible frame, and the skin arrays keep the frozen joint positions. NearSkin (line 699), ClearanceAlong (line 423) and ShortestWayOut (line 449) then test points against that invisible glove, although their docs promise false or 0 when the glove is not shown.
   trigger: Weapon's-arms mode with an arm-rig weapon, or carrying an ammo box or medipack (HiddenByHeld). Consumers: HeldWeapon.cs:1563 (RackSolid, which feeds PalmOnPart at ReloadInteractions.cs:1664 and so the arm anchor), HeldWeapon.cs:1544 and 1658 (drawn-handle and pistol support solids), and ReloadInteractions.cs:1777 and 1795 (keep-out of the off hand, KeepEmptyHandOut and KeepOutOfGun). An empty hand that reaches the frozen position is pushed out of a glove nobody can see.
   fix: In SetVisible, when visible is false, set _skinValid = false (for example `if (!visible) _skinValid = false;` before the early return). That makes NearSkin, ClearanceAlong and ShortestWayOut report nothing while the glove is hidden.
   skeptic (correct): REAL, high: Mechanism confirmed. _skinValid is written only in UpdateSkin (src/Rig/HandModel.cs:677). Apply() calls SetVisible(!Suppressed && !HiddenByHeld) at line 511 and returns at 512-515, before UpdateSkin() at line 667. So while the glove is hidden, _skinValid keeps the value from the last visible frame (true), and the _skinA/_skinB/_skinR arrays are frozen too. NearSkin (699), ClearanceAlong (423) and ShortestWayOut (449) guard only on _skinValid, and no consumer checks Visible first (the only read of Model.Visible is AutoTest.cs:2421).

Two consumer chains reach the stale glove on a visible hand:

It calls UpdateGraspAnchor (ReloadInteractions.cs:1612), and an empty off hand has role Free (WeaponSystem.cs:155/162). That reaches KeepEmptyHandOut (1694-1695), which sets _keepOutHand to the dominant model (1772), tests NearSkin inside _keepOutBlocked (1779), and calls ShortestWayOut to set off.Model.KeepOut (1783). Off-hand Apply applies KeepOut while the off glove is visible (HandModel.cs:541-542), so the empty glove is visibly pushed up to 10 cm away from an invisible glove.
2. Arm-rig path (Suppressed). HeldWeapon.cs:1110 sets Suppressed on all hands. While racking, the off hand has role Slide (ReloadInteractions.cs:1438). RackSolid(main) (HeldWeapon.cs:1563) includes the frozen dominant NearSkin, so UpdateGraspAnchor's PalmOnPart (1666) yields a GraspAnchor (1707).
