Confidence: medium-high that the two boxes differ on the logged guns and that the code reads as described (every line above was read). Medium on the player-visible effect, which needs a headset check on ARS HK416 and MP9.

2. Skill: BUG HUNT - the first magazine after a dry draw is built on the analysed line, before the in-game fit tilts it
Complaint: general (a magazine goes in on a wrong line on some guns; the first insert after a dry draw)
File: src/Weapons/HeldWeapon.Shape.cs:269, 276, 510; src/Weapons/MagazineProp.cs:75, 330; src/Weapons/MagazineProp.Look.cs:38-40, 633; src/Weapons/ReloadInteractions.Magazines.cs:259
Quote:
  HeldWeapon.Shape.cs:269:  "                || !_magSolidShown || Ammo == null || !Ammo.UsesDetachableMag || !Ammo.MagInserted || d.Action == ActionType.SingleShot"
  HeldWeapon.Shape.cs:510:  "                d.MagEjectAxis = -(Quaternion.AngleAxis(bestAngle, right) * in0).normalized;"
  MagazineProp.cs:75:       "        public readonly Vector3 InsertDirLocal;"
  MagazineProp.Look.cs:38:  "            Axes(d, kind, out Vector3 insertGun, out Vector3 frontGun);"
  MagazineProp.Look.cs:633: "            insertGun = -d.MagEjectAxis;"
  ReloadInteractions.Magazines.cs:259: "            MagazineProp prop = MagazineProp.Create(Rig, kind, rounds);"
What is wrong: FitMagazineLine runs only with a magazine seated (MagInserted, and a seated volume that needs the part shown). A gun drawn dry therefore has no fitted line. The magazine taken from the pouch (TakeFromPouch, line 259) is built from the analysed d.MagEjectAxis, and InsertDirLocal is readonly, so that prop keeps the un-tilted line for its whole insertion. The fit runs only after seating and rewrites d.MagEjectAxis (line 510) for props made later. Only the first insertion after a dry draw is affected, and only on guns that are not in the offline table and whose fit tilts them. The logs show tilts on: SL-DEFENDER#sniper (-3 and -6 deg; reports/shots/auto1/game-log.txt:916, reports/shots/ab1/game-log.txt:50), AUTOMATICO AKIMBO (12 deg; reports/shots/auto1/game-log.txt:293), RIPCORD#PP90 (12 deg; reports/shots/auto1/game-log.txt:784), and M1 GARRET (15 deg, same fit log family).
Trigger / what the player sees: Draw an SL-DEFENDER (or AKIMBO, RIPCORD) with no magazine in it, take one from the pouch and push it in. It slides along the untilted line, which is the line the fit was built to move away from the gun's walls. Later reloads use the tilted line. The seated place is the same; the approach is what differs.
Proposed change: Make the live prop follow the rig's line. Drop `readonly` on InsertDirLocal, FrontLocal, TipLocal and BaseLocal (MagazineProp.cs:75-76, 330-336) and recompute them from d.MagEjectAxis when FitMagazineLine changes it, updating a held prop if there is one. Alternatively, let the fit's volume measure run with the seated part hidden, so the first insertion already has the fitted line.
Confidence: medium. The gates and the readonly field were read directly, and the tilts are in the logs. I did not run a dry draw, so the first-insert effect is inferred from the gates.

What is wrong: For a magazine parked away at rest, the seat's position becomes the reload sample nearest the bore (loop at 369-375), but its rotation stays the rest pose (RelIdle). 5. Skill: BUG HUNT - sub-weapon keys carry a path suffix, so the offline magazine table never matches them
Complaint: general (the offline table is applied on one path but not the other)
File: src/Weapons/WeaponAnalyzer.cs:145-153, 198; src/Weapons/MagLineTableApply.cs:27; src/Weapons/MagLineTable.cs:10-112 (the keys)
Quote:
  WeaponAnalyzer.cs:152:       "                key += path.ToString();"
  MagLineTableApply.cs:27:     "            if (d == null || d.Key == null || !Lines.TryGetValue(d.Key, out Vector3 line) || line.sqrMagnitude < 0.5f)"
What is wrong: KeyOf appends the sibling path for any weapon with a Weapon ancestor, so a sub weapon's d.Key carries a suffix, for example "HK416-D#M320身子/1/0/19". The table is keyed on the plain "entry#prefab" form (MagLineTable.cs:10-112), so a sub weapon never receives its measured line. It gets the in-game fit instead (HeldWeapon.Shape.cs:277, From(d) is false).
Evidence: five suffixed keys in sandbox/data/weapons/*/rig.json: "HK416-D#M320身子/1/0/19", "HK416-D/S#M320身子/1/0/19", "QBZ192-D#QLG榴弹发射器/1/0/21", "QBZ192-D/S#QLG榴弹发射器/1/0/21", "PATRIOT GL#AR-15 Nade Launcher/0/8". All five are launchers, so the export shows no magazine effect.
Trigger / what the player sees: A magazine-fed sub weapon whose plain key is in the table gets the in-game fit instead of its measured line.
Proposed change: In MagLineTable.Apply and From, strip a trailing run of "/<digits>" from the key before the lookup (the table's keys never carry one), so sub weapons get the measured line as top-level guns do. Keep the MaxTurn guard.
Confidence: high that the lookup misses suffixed keys (KeyOf and Apply read directly). Low on player impact: only launchers appear in the exports, and no magazine-fed sub weapon is confirmed.
